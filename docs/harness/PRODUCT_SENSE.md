# 产品原则

规划产品功能、调整用户行为或评估需求价值时读取本文。

1. 从使用场景确定目标：写清谁在什么情况下遇到什么问题，以及完成后能做什么；功能数量和实现规模不作为价值依据。
2. 区分既定要求与新增判断：已有产品资料时遵守已确认行为；资料缺口与多轮对话中的重要歧义向用户确认。
3. 围绕完整操作设计：覆盖入口、关键动作、结果与必要的失败反馈；保持术语和同类操作一致，优先复用已有交互。
4. 控制需求范围：优先完成核心场景。新增能力应说明实际用途及代价；涉及目标或范围的取舍交用户决定。
5. 用行为证明价值：为核心目标提供可核对的验收条件。采用满意度、接受率等指标时，先明确采集对象与口径，不用技术完成状态代替用户结果。

规格按[产品规格写法](styles/product-spec.md)记录，UI 方案按[前端与交互原则](FRONTEND.md)设计。
