# 架构说明写法

项目 `docs/ARCHITECTURE.md` 帮助人和 Agent 定位现行系统，按需链接细节；软件设计取舍按[设计记录写法](design-doc.md)保存。

1. 开头标明描述对象与核对范围，说明系统当前具备什么能力及主要入口。
2. 按职责解释主要模块、依赖方向、关键数据流及外部系统；目录只列定位工作所需的层级。
3. 写清影响后续修改的稳定约束及禁止跨越的依赖，并给出关键代码、契约和运行说明入口。
4. 目标方案与学习推演放在相应设计或知识文档，标明状态并链接；现行架构只描述已核对的实现。
5. 模块职责、入口或依赖发生变化时同步更新；核对文档声明时读取对应实现，不用旧设计直接推断当前状态。
