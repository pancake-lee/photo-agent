# 产品规格写法

本文规定 `docs/product-specs/` 的内容与写法，产品判断遵循[产品原则](../PRODUCT_SENSE.md)。

1. 开头按[规划类型](../top/mode-planning.md#规划类型)标明输入与设计范围。已有产品文档或设计稿时，区分提炼的既定要求与本次补充的产品、UI 设计。
2. 正文记录目标、产品行为、失败场景和验收条件；设计方案与取舍链接对应设计文档。

```markdown
# <产品规格主题>
状态：<待审批或已确认>
规划类型：<资料驱动规划或简述需求规划>
需求来源：<reference 链接，或“用户对话”，结论见正文>
本次设计范围：<本次新增或调整的内容>

## 需求结论
<目标用户、使用场景、要解决的问题及成功表现>

## 范围与行为
<本次范围、范围外事项、核心操作与可观察结果>

## 边界与失败场景
<影响需求的空状态、错误输入、权限或中断等场景及预期行为>

## 验收条件
<稳定编号：前提与输入/操作 → 可核对结果>

## 关联设计
<必要的 UI 或技术方案入口>
```

验收条件供设计、生成和评估共同引用；性能或数量要求写明条件与阈值。只写已确认的约束，不用主观形容词代替可观察结果。

外部资料已完整覆盖的部分保留准确入口，只补充本次差异、歧义裁决与验收条件。没有实际内容的可选章节省略；关键取舍与澄清按[对话需求记录](../top/mode-planning.md#记录对话需求)补充。
