# 文档类型与写法

本文件记录个人文档类型的写法。只有写出规则的类型才有对应约束；空标题仅用于保留分类，不推断或套用其他类型的规则。

规则应提炼同类文档可复用的组织与表达原则，不将单次任务的栏目、术语或操作步骤固化为通用要求。本文自身的规则编写与修订也遵循此原则。

## 简洁写法

适用于工作记录、分析与准备清单；知识笔记等其他类型不自动套用。

- 默认使用短列表，直接记录事实、判断、缺口、优先级与行动；一条一个要点，简短标识放在开头。
- 使用书面记录口吻，删除对用户说话的开场、过渡、自我解释和结尾总结。
- 同一结论只写一次；理由、证据和边界紧邻对应要点，较长材料用链接引用，不反复展开。
- 只保留影响当前判断或行动的信息；不主动扩写背景、概念教学、完整推演、详细日程或逐项验收标准，用户要求时再展开。
- 精简应删除重复与铺垫，不将长段落改成同样冗长的列表；保留会改变结论的事实与不确定性。

## 工作记录

用于保存一项工作遇到的问题、依据、决策变化和当前做法，便于以后查阅与接续。

- 开头标明更新时间，并链接实现位置和主要证据来源。
- 按“问题与证据 → 决策过程 → 当前状态或操作 → 边界”组织；没有对应内容时省略该部分，不为凑结构留空壳。
- 以列表记录，一条只承载一个主要事实、决定或动作；避免用长段落复述对话。
- 保留改变方向的关键节点：考虑过什么、最终选择什么、为何调整。重复的方案推演和已失效的操作细节可以压缩。
- 区分已核实事实与推断；数据写明来源或时间，推断写明依据及可信程度。
- 当前操作只写现在需要执行的步骤，旧方案留在决策过程，不混入操作清单。
- 将统计口径、无法补全的数据和适用边界集中列出，避免在各节反复提醒。
- 语气平实、简洁、可追溯；不写成聊天复述或宣传文案。

## 分析与准备清单

- 围绕文档要支持的判断或行动组织内容，按信息关系分组，不预设固定栏目或保留空分组。
- 区分事实、判断与信息缺口，不将尚未验证直接写成否定结论。
- 行动项明确优先级与具体目标；理由、方法和验收要求仅在影响理解或执行时补充，不逐项机械展开。

## Skill 维护

- 按决策权、推理需求和执行责任区分人、LLM 与程序的职责，不按文件名或维护者机械划分。
- 保留用户对可定制规则的定义权，将规则意图、模型判断方法和程序实现分别维护；规则已被程序采用，不意味着可以删除其定制入口。
- Skill 聚焦模型完成任务所需的指引与上下文，已由程序可靠执行的机制不重复转化为模型的逐次分析要求。
- 各层通过清晰的输入输出约定衔接，保留理解结果所需的语义与适用边界，不要求使用者同时了解全部实现细节。
- 按实际复杂度组织资料，按任务需要读取；不预设固定目录、栏目或文件数量，同一约定尽量集中维护，其他位置引用。
- 精简上下文时保留维护价值，将移出的设计依据、取舍和演进记录另行保存，区分历史方案与当前做法。
- 反馈与修改落到对应职责层，并核对层间约定是否仍一致；区分规则调整、实现变更和实际生效，不混淆三者。
