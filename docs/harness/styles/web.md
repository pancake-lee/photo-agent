# Web 代码规范

## 验证方式

- 优先使用代码层面检查或自动化测试，不必例行启动开发服务器并抓取页面检测，以免浪费 token
- 不要为用户启动服务。修改代码后，由用户自行运行 `pnpm dev` 等命令

## 包管理器

- 除非用户指定，或项目明显使用其他包管理器，否则优先使用 `pnpm`，而不是 `npm`
<!-- harness:end -->

## Web 前端（web/）

- 编写或修改前端布局前，先读 `docs/harness/FRONTEND.md`，检查设计方案是否符合基本的规则。仅逻辑修改则无需关心这个文档
- 优先使用 pnpm，而不是 npm，除非用户指定或目录/代码明显不是使用 pnpm
- 无需为验证改动而启动 Dev Server 并抓取页面检测，消耗太多 token
