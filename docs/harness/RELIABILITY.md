# 可靠性原则

涉及外部依赖、长任务、并发、持久化或恢复流程时，按本次改动读取相关要求。

1. 定义完成状态：明确成功、部分完成、失败与取消的含义。以可观察结果判断完成，避免仅凭无异常或进程退出推断成功。
2. 区分失败原因：配置、数据、逻辑错误优先修正根因；只有可恢复的暂时故障才采用重试或降级，并说明停止条件。
3. 控制资源与副作用：按实际风险确定超时、尝试次数和取消方式；重复执行可能产生副作用时，明确是否允许重试及如何防止重复处理。
4. 保留必要诊断：记录能关联关键步骤与结果的信息。新增日志或 Trace 依据具体排障、验收或分析需求，避免重复输出完整上下文。
5. 验证关键失败：对受影响流程选择失败、中断或恢复场景；测试应证明最终状态符合预期，资源可释放。回归范围按[完成门](top/mode-generation.md#完成门)权衡。

性能、可用性及成本目标由项目按实际用途确定，记录测量条件；不把通用示例数值作为默认承诺。
