# 生成模式

生成模式按已确认的方案实现，完成自检并更新任务记录，将产物和验证结果交给评估模式。

## 进入模式

用户表达“按方案执行”“开始开发”“实现这个”等意图时，进入生成模式。执行对象为指定方案或状态为“已规划”的任务。

## 读取依据

读取任务方案、验收条件、相关代码和 `docs/ARCHITECTURE.md`。
按需查阅 `docs/harness/DESIGN.md` 等任务原则、`docs/harness/styles/` 中的规范及任务引用的资料。

读取 `docs/backlog.md` 对应的 Task 或 Bug 及依赖；按需查阅所属 Feature 的详细设计和 Epic 的概要约束。

## 实现与自检

1. 按计划实施，运行与改动相关的检查并修复问题。代码变更涉及可复用逻辑、功能行为或核心算法时，使用能覆盖改动的测试，优先复用已有用例。
2. 核对验收：按下述完成门选择检查，记录实际命令、结果和未验证项。
3. 同步文档：更新 backlog 条目的依赖、状态、验证记录和验收项；影响所属 Epic/Feature 的目标或约束时，同步对应设计。
4. 清理重复：删除文档中仅重复代码的实现片段，保留需求、设计理由和外部约束。

## 完成门

1. 选择证据：对照验收条件，选择成本低且足以证明结果的检查；端到端用例按规划执行，不叠加所有验证手段。
2. 使用诊断记录：出错排查时查看日志或 Trace；缺少端到端测试且需要运行证据时，也可检查对应记录。无报错不能代替效果验证。
3. 权衡回归：影响范围大、回归成本低时优先运行；改动局部、风险低且回归成本高时，可推迟完整回归至版本末，保留本次直接验证。涉及共享接口或关键流程时，及时验证受影响路径。
4. 记录结论：写清证据与验收条件的对应关系。推迟的回归记录范围、理由和执行时点；证据不足时保留未验证项，不宣称验收通过。

## 临时产物

开发和验证产生的临时程序、测试数据、脚本及日志，统一输出到项目根目录 `./local/` 的任务子目录。

## 轻量反馈

按[反馈路由](HARNESS.md#反馈路由)处理刚交付工作的单项局部反馈时，先在反馈归属的任务条目记录范围和预期，完成轻量规划后直接实施。以直接覆盖本次变化的最小检查验证，例如相关类型检查、既有用例或可核对的局部行为。将改动与一个快速试用步骤交给用户，保留 Git 未提交状态。完整评估和本地提交分别按用户要求执行，切换到全流程模式时按该模式处理。

## 任务状态

`WIP` 表示 AI 仍在实现或自动验证。无需用户操作时，AI 完成验收后将任务标为 `Done`。

按完成门选定的检查结束后，如果还需用户快速试用或真实环境验收，将任务标为“待用户验收”。记录“（用户）”操作、预期结果和最小回复方式，并在交付回复中明确请求验收。

用户确认验收成功后，在同一轮将任务标为 `Done`，同步任务总览与关联文档，不反向核验用户的结论或要求补充证据。

## 输出与交接

将变更范围、自检结果和未验证项写入任务记录。
提供任务与方案入口，按[反馈路由](HARNESS.md#反馈路由)交给[评估模式](mode-evaluation.md)或用户试用。自检结果与独立评估结论分别记录。

## 触发与执行细则

**触发词**：`按方案执行` / `开始开发` / `实现这个` / `完成开发`

**流程**：

1. 确认执行对象：指定方案文档、或 `docs/backlog.md` 中状态为「已规划」的条目
2. 读方案文档 + `docs/ARCHITECTURE.md` + `docs/harness/styles/code.md`
3. 按任务条目逐步实施，按[完成门](#完成门)选择自检
4. 全部实现完成后，检查相关设计文档，清理仅重复代码实现的片段，保留仍用于协作的契约与设计理由。
5. **文档同步（必须逐项完成，不可跳过）**：
   - [ ] 更新 `docs/backlog.md` **任务总览表格**中对应行的状态
   - [ ] 更新 `docs/backlog.md` **任务详情区**中对应条目的状态字段
   - [ ] 在任务条目中勾选已完成的实施步骤及验收项，记录验证依据
6. **验收关单（必须逐项完成，不可跳过）**：
   - [ ] 交付验收前，AI 完成按本次改动的[完成门](#完成门)选定的检查，记录实际结果
   - [ ] 无需用户操作的验收，由 AI 在本轮运行并核对；全部通过后将任务改为 `Done`，不得以 `WIP` 滞留
   - [ ] 需要用户试用或真实环境验收时，改为 `待用户验收`。在 backlog 任务详情中写出 `（用户）` 操作、预期结果和最小回复方式
   - [ ] 最终回复中主动、醒目地请求这一个用户验收，不将"待验收"埋在变更摘要中
   - [ ] 用户确认验收成功后即终态：AI 在同一轮将任务更新为 `Done` 并同步总览和相关中枢文档，不反向核验用户的验收结论，也不要求用户补充证据。验证流是单向的（AI 自动验证在前，用户人工验收在后），避免互相验收的循环
