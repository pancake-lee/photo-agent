# 项目管理模式

**触发词**：`版本归档` / `归档` / `里程碑` / `版本规划` / `迭代计划`

**流程**：

1. 确认任务类型：版本归档、里程碑规划、还是 backlog 治理
2. 读 `docs/backlog.md` + `docs/version/` 了解当前版本状态
3. **归档前评估门槛**：当用户明确表达"准备版本归档，给 backlog 全部 Done 任务做评估"或同义意图时，先进入 [评估指南](../eval-guide.md) 的「归档前阶段合理性专项检查」，完成报告和问题登记后再由用户决定是否继续归档。该检查不适用于普通任务收尾
4. **全 Done 主动提醒**：当任务总览中除明确不执行状态（如 `暂缓`、`已取代`、`已拒绝`）外均为 `Done`，可主动询问用户是否需要执行归档前阶段合理性专项检查；一次全 Done 状态只提醒一次，用户暂缓后等待任务总览变化或用户主动提归档再询问
5. 按任务类型执行：
   - **版本归档**：识别 Done 条目 → 创建 `docs/version/vX.Y.Z.md` → 精简 backlog 至仅剩未完成条目 → 更新决策历史
   - **里程碑规划**：梳理剩余 backlog → 评估优先级和依赖关系 → 排定下一版本范围建议 → 更新 backlog 状态
   - **backlog 治理**：交叉比对 backlog.md 和实际代码 → 识别过时/遗漏条目 → 给出清理建议
6. 给出执行结果和变更摘要，等用户确认
