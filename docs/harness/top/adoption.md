# 项目接入与迁移

接入目标是让项目沿用共同流程，并保留真实的产品、架构和运行约束。

## 核对现状

明确目标仓库与接入范围。读取现有入口、规则、需求、设计、任务和验证方式，列出保留、替换与仅属于项目的内容。

共享文档记录流程与通用判断；语言偏好按采用情况配置；项目架构、依赖库、数据库策略、运行命令与发布条件留在项目。接入前解决影响行为的规则冲突。

## 准备变更

以[入口文件](../../../AGENTS.md)及[总纲](HARNESS.md)为导航，按需采用配套原则与规范。项目 `README.md` 保留产品介绍和运行入口，`docs/ARCHITECTURE.md` 按[架构说明写法](../styles/architecture.md)基于真实实现编写。

将旧需求、设计、任务映射到规格、设计、backlog 与版本记录；保留稳定编号和可追溯关系。归档只读，旧快照通过活动索引关联，不批量改名或回写。

已有 `CLAUDE.md` 等工具入口时，采用能保持单一内容来源的引用或链接机制；核对工具实际加载方式，不创建多份需要人工同步的规则正文。

## 验证接入

先检查文档职责、相对链接和入口，再用代表任务验证规划、生成与评估交接。确认新会话能找到目标、当前状态和验证依据，且不需要加载整个知识库。

核对项目既有检查是否仍可使用，用户操作是否明确，推迟的回归是否有执行时点。缺少环境的检查如实记录，不将接入静态检查表述为流程已实证有效。

## 发布与维护

将具体差异、适配决定和验证结果交用户审阅。批准后仅向明确授权的目标应用；发布记录保留来源版本与项目差异，支持复核和回退。

迁移脚本只能在核对目标路径、覆盖范围及保留策略后使用；不能因旧脚本存在就直接向新结构同步。

## 双入口维护

- **协作规则双文件一致**：`CLAUDE.md` 与 `AGENTS.md` 是 Codex 和 Claude 工作流共同使用的项目规则，项目专有内容应保持一致；新增规则、索引和流程说明也应同时维护两份文件

> 维护原则：CLAUDE.md 与 AGENTS.md 是同一套项目规则在 Claude/Codex 工作流中的双入口，项目专有内容修改时同时维护两份文件。
