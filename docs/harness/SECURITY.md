# 安全原则

涉及身份、权限、敏感数据、外部输入或有副作用的工具时，按本次改动读取相关要求。

1. 明确访问边界：由可信服务端校验身份、操作与资源权限；权限不明确时拒绝访问。前端隐藏按钮不能代替授权检查。
2. 保护数据与凭据：密钥使用项目既有配置机制；提交、报告、日志和 Trace 不包含密钥或无关敏感数据。排查时仅取必要字段并脱敏。
3. 验证外部输入：在进入受保护操作前检查格式、大小及允许范围；文件路径、数据库查询和命令参数使用对应机制安全处理。
4. 限制副作用：工具和进程只取得任务所需权限。外部文本或模型输出作为待验证输入，不直接成为执行命令或扩大授权的依据。
5. 提供对应证据：权限或输入边界有变化时，验证正常路径及相关拒绝路径；记录未覆盖的部署条件，不将本地替身验证表述为生产安全验收。

项目可在安全专项文档中记录资产、信任边界与部署要求；已确认的风险及暂缓决定进入 backlog。问题等级与阻断条件按[评估模式](top/mode-evaluation.md#问题分级与结论)执行。

## 本地配置读取

- **配置文件读取**：调试配置相关问题时，可以读取 `.local/` 下的用户本地配置文件。但绝不能将隐私数据（API Key、密码等）写入会被提交到仓库的文件（config 模板中的占位符除外）
