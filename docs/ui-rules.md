# UI 美学规则

> AI 生成前端代码时参考的基础视觉设计原则。面向非设计师，每条规则可操作、可验证。
> 来源：行业公认设计原则（Gestalt 原理、Material Design、Ant Design 设计语言、WCAG 可访问性标准等）。

---

## AI 使用说明

**每次给出 UI 方案或代码时，必须在回复末尾附上「规则引用」区块**，格式如下：

```
> 🎨 规则引用：1.1（8px 网格）, 1.2（邻近性）, 4.1（60-30-10）
```

只需要列出编号和规则简称，不需要展开说明。规则编号即锚点，方便回溯。

**用途**：

- 当我看到不符合审美的设计时，可以根据引用定位到具体规则，判断是规则本身有问题还是执行有偏差
- 如果某条规则反复导致我不满意的结果，我会要求修改或删除该规则
- 换句话说，这些规则不是教条，是待验证的假设，引用机制就是验证的入口

## 一、布局与间距

### 1.1 间距体系：8px 网格

所有间距（padding、margin、gap）使用 8 的倍数。紧凑场景允许 4px 作为半步。

- 组件内部间距：`8px` / `12px` / `16px`
- 组件之间间距：`16px` / `24px` / `32px`
- 区块之间间距：`32px` / `48px` / `64px`

同层级元素的间距必须一致，不要出现 10px 和 12px 混用的情况。

### 1.2 邻近性：同类聚合，异类隔离

功能相关的元素用较小间距（8-12px），功能无关的区块用较大间距（16-24px）。用户靠距离判断元素归属，间距差异不够大时归属会模糊。

- 标签组内各标签间距一致；标签组与相邻按钮组之间留更大间距
- 表单中，label 离自己的 input 近，离上一个 input 远

### 1.3 对齐：每个元素都应对齐到某个参照物

- 同一纵列的元素左对齐或右对齐，不要混用
- 卡片内同类信息（标题、描述、标签）起始位置对齐
- 数字型数据右对齐（方便用户比较位数），文本型数据左对齐
- 避免"居中对齐一切"，左对齐是最易阅读的对齐方式

### 1.4 阅读方向：从左到右，先信息后操作

同一行内，左侧放数据/信息展示，右侧放操作入口。用户先理解现状，再做操作。

## 二、视觉层次

### 2.1 每屏只有一个主焦点

通过尺寸、颜色、对比度让最重要的元素最显眼。如果所有元素都在"喊叫"，就没有元素能被听到。

- 每个页面/区块应该能回答：用户第一眼应该看哪里？
- 标题 > 核心数据 > 辅助信息 > 操作入口，按此顺序递减视觉权重

### 2.2 信息层次：标识 → 摘要 → 详情 → 操作

每个功能区块按以上顺序垂直排列：

- **标识**：这是什么（标题、名称）
- **摘要**：关键指标的一行汇总
- **详情**：完整数据，可折叠
- **操作**：用户能做什么

### 2.3 留白不是浪费

内容密度越高，用户理解越慢。适当的留白让信息分组清晰，降低认知负担。

- 卡片内边距不小于 16px
- 段落/区块之间至少留 16px 呼吸空间
- 不要为了"塞下更多内容"压缩间距

## 三、排版

### 3.1 限制字号层级

一个页面中字号不超过 3-4 级。层级越多，用户越难建立"这是什么级别信息"的直觉。

建议层级（以 16px 基准为例）：

- **页面标题**：20-24px，粗体
- **区块标题**：16-18px，粗体
- **正文/内容**：14-16px，常规
- **辅助/说明文字**：12-13px，常规或灰色

### 3.2 行高与行长

- 正文行高：`1.4-1.6`（中文可偏下限，英文偏上限）
- 标题行高：`1.2-1.3`
- 正文最大行宽：`65-75` 个字符（中文约 35-40 字），过宽时阅读视线难以换行定位

### 3.3 字重对比优于字号对比

区分层级优先用字重（regular / medium / bold），而不是不断放大字号。同一字号下 bold 和 regular 的对比已经足够清晰。

## 四、色彩

### 4.1 60-30-10 法则

页面色彩分配比例：

- **60% 主色**：背景色（白/浅灰），撑起整体基调
- **30% 次要色**：容器色（卡片、侧边栏背景），区分区块
- **10% 强调色**：品牌色/主色调，仅用于最关键的可操作元素（主按钮、选中态、链接）

### 4.2 语义色保持一致

同一颜色在全局表达同一语义。不要在一个地方用绿色表示"成功"、另一个地方用绿色表示"普通标签"。

- **蓝**：信息/中性/进行中
- **绿**：成功/通过/正常
- **黄/橙**：警告/需注意
- **红**：错误/失败/危险

### 4.3 对比度达标

- 正文文本与背景对比度不低于 `4.5:1`（WCAG AA）
- 大号文本（18px+ 粗体）不低于 `3:1`
- 灰色文字不要过浅，最低 `#767676` 左右（白底上）

### 4.4 灰色是设计师最好的朋友

大量 UI 信息用灰色层级表达，而非增加颜色种类：

- 深灰（`#333-#555`）：主要文字
- 中灰（`#666-#999`）：次要文字、图标
- 浅灰（`#ccc-#e8e8e8`）：分割线、禁用态、占位符

## 五、组件状态

### 5.1 每个可交互元素至少覆盖四种状态

- **默认**：正常展示
- **悬停（hover）**：光标移入时给出视觉变化（变色、加深、微放大）
- **激活/按下（active/pressed）**：点击瞬间的反馈
- **禁用（disabled）**：灰显 + 降低透明度（`opacity: 0.4-0.5`），不隐藏

### 5.2 按钮文案保持稳定

按钮的文案描述"动作"，不应随数据状态变化。用户靠位置和样式识别按钮，文案一变就需要重新阅读判断。

- 始终用同一个动词短语，不因当前数据有无而改变措辞
- 是否已有数据通过按钮样式区分（primary / outline / default），不靠文案

### 5.3 禁用优于隐藏

当前条件不满足时，禁用按钮并灰显，而不是隐藏它。用户需要知道"这个操作存在，只是当前不可用"。组件突然出现/消失会让用户怀疑页面稳定性。

### 5.4 零值和空状态要显式处理

- 数值型指标无数据时显示 `0`、`0/0`、`—`，不隐藏整个指标区
- 列表为空时显示空状态提示（"暂无数据" + 可选的操作引导），不展示空白页面
- 加载中显示骨架屏或 spinner，不展示空白

## 六、交互反馈

### 6.1 操作必须有即时反应

用户每次操作后，100-300ms 内必须有可见反馈：

- 按钮点击：样式变化（active 态）、加载中态
- 数据提交：按钮 loading + 禁用，防止重复提交
- 数据加载：骨架屏（结构性内容）优先于全局 spinner（整页空白）
- 操作结果：成功/失败提示（toast），告知结果

### 6.2 过渡动画的原则

- 持续时间：`150-300ms`，不超过 400ms（再慢会让用户觉得卡顿）
- 缓动函数：用 `ease-out`（进入）和 `ease-in`（离开），避免 linear
- 什么需要动画：元素的出现/消失、状态切换、页面跳转
- 什么不需要动画：静态内容的首次渲染、纯数据刷新

### 6.3 可点击区域足够大

- 按钮/可点击图标最小点击区域：`32×32px`（移动端 `44×44px`）
- 相邻可点击元素之间至少 8px 间距，避免误触

---

## 七、内容优先

### 7.1 减少视觉噪音

- 去掉不必要的分割线——留白已经足够区分区块
- 去掉不必要的边框——卡片阴影或背景色差已经表明了边界
- 图标不是必须的——纯文字按钮同样清晰，不要为了"好看"硬加图标

### 7.2 一操作一入口

同一功能在同一个页面只保留一个入口。多处出现同一按钮会让用户怀疑它们是否真的做同一件事。

### 7.3 按用户关注度排列，而非按实现复杂度

最重要的信息放在最显眼的位置（顶部、左侧），而非最方便实现的位置。不要因为"这个数据好取"就把它放在 C 位。
