# Photo Agent — 产品需求文档

## 1. 产品概述

### 1.1 产品定位

Photo Agent 是一个面向**个人摄影爱好者**的 AI 选题助手。它通过对摄影作品进行 AI 视觉描述、建立时间线与标签知识库，让用户可以用**自然语言**与自己的照片库对话，实现智能检索、摄影档案问答，以及 AI 主动推送选题建议。

> **一句话定义**：让你的摄影照片库"会说话"的 AI Agent。

### 1.2 目标用户

- **摄影爱好者**：积累了大量照片，靠文件夹和文件名难以快速定位特定作品
- **创作者**：想基于历史作品分析风格特点，获取拍摄和发布建议

### 1.3 核心价值主张

- **找照片困难**：翻文件夹、靠记忆命名 → 自然语言描述即可检索
- **作品信息分散**：拍摄时间、地点、主题散落在各文件夹 → 统一照片库，Web 管理 + AI 对话
- **多维筛选困难**：EXIF 工具逐个查看 → 用自然语言按光线、色调、场景、构图、情绪组合筛选
- **创作灵感枯竭**：不知道发什么、经常断更 → AI 定期扫描照片库，主动推送选题建议（照片组合 + 发布角度），用户像主编一样审阅打分
- **风格认知模糊**：凭感觉判断自己的摄影风格 → AI 基于历史作品做数据分析

## 2. 功能需求

### 2.1 功能优先级

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 智能检索 | 自然语言搜索照片，支持语义描述 + 结构化维度组合过滤 |
| P0 | 摄影档案问答 | 基于照片库的统计和问答（拍了多少、在哪拍的、用什么器材） |
| P0 | Web 照片管理 | 上传、浏览、筛选、排序、删除，VLM 预处理和向量索引队列可视化 |
| P1 | 选题建议（主题发现） | AI 主动扫描照片库，推送选题提案（照片组合 + 发布角度），用户审阅打分 |
| P1 | 摄影主题分析与创作建议 | 用户主动提问，AI 基于历史作品深度分析风格、给出拍摄建议 |
| P2 | 相似照片聚类 | 自动发现照片库中的视觉主题组合，AI 生成主题标签 |
| P2 | 时间线关联分析 | 跨时间线的关联分析（季节主题、地点重现、风格演变） |

### 2.2 P0 — 智能检索

**用户故事**：

> 我想输入"2024 年在云南拍的雪山人像"，系统能返回匹配的照片列表和文字说明。

**功能描述**：

- 用户通过 Web 对话界面输入自然语言查询
- 系统自动判断查询意图，分四种策略：
  - **结构化查询**：统计类问题（"我有多少张照片"）和 EXIF 筛选（"Canon 拍的照片"、"ISO 大于 1600"），自动生成数据库查询并返回结果
  - **语义检索**：内容描述类问题（"海边的日落"、"有氛围感的街拍"），基于 AI 视觉描述做向量匹配
  - **工具调用**：需要列举或操作资源时（"列出所有时间线"），自动调用后端 API 获取数据
  - **组合查询**：同时涉及结构化维度 + 语义内容时（"逆光的雪山照片"、"蓝调时刻的人像"），两侧并行执行取交集
- 返回匹配照片列表（缩略图 + AI 描述 + 结构化属性），AI 回复标注使用的查询策略
- 支持多轮对话追问

### 2.3 P0 — 摄影档案问答

**用户故事**：

> 我想问"我拍过几次海边日出？都在哪些地方？"，AI 能基于照片库回答。

**功能描述**：

- 用户可就自己的摄影档案自由提问，AI 自动选择查询策略回答
- 照片导入时自动提取 EXIF 信息（相机、镜头、ISO、光圈、焦距、GPS）
- 照片经 VLM 预处理生成 AI 视觉描述，同时提取结构化属性（主体类型、主色调、场景、光线特征、情绪氛围、构图特点）
- AI 回答时展示相关照片缩略图和结构化属性信息

### 2.4 P1 — 选题建议（主题发现）

**用户故事**：

> 我想让 AI 定期扫描我的照片库，主动推送选题建议（推荐照片组合 + 发布角度），我像主编一样审阅和打分。

**功能描述**：

- AI 不等用户提问，主动分析照片库，基于编辑视角发现可发布的叙事主题
- 每条选题包含：叙事角度描述（30-60 字）、推荐照片序列（5 张以上，时间跨度 ≥ 7 天）
- 选题结果持久化存储，按时间倒序展示历史列表，支持回溯对比不同批次的选题质量
- 五星评分体系：点亮/取消任意分值，hover 预览临时高亮，三态视觉区分（空心/实心/发光），取消评分有 tooltip 提示
- 可删除不再需要的历史选题

**区别于 §2.5「摄影主题分析与创作建议」**：§2.7 是 AI 主动推送（push），§2.5 是用户主动提问（pull）。两者互补：日常有 AI 提案保底，特定需求时用户可主动深入分析。

### 2.5 P1 — 摄影主题分析与创作建议

**用户故事**：

> 我想和 AI 讨论"今年生日想送什么礼物"，AI 能基于历年同期照片提供建议。

**功能描述**：

- 用户提出主题或创作方向，AI 检索相关历史作品（时间线、主题、风格）
- 基于素材生成分析建议或拍摄方案
- 输出纯文本（不生成图片/视频）

### 2.6 P2 — 相似照片聚类

**用户故事**：

> 我想知道我的照片库中自然形成了哪些视觉主题组，每组可以怎样发一组图。

**功能描述**：

- 基于 AI 视觉描述自动聚类，发现照片库中视觉相似的照片组合
- 每个聚类自动生成主题标签（如"城市蓝调时刻""云南雪山系列"）
- 聚类结果按视觉连贯性排序浏览，支持评估标题质量

### 2.7 P2 — 时间线关联分析

**用户故事**：

> 我想了解"我每年春天都拍了什么主题"，AI 能做跨时间线的关联分析。

**功能描述**：

- 基于全部素材的描述和时间线标签，AI 回答跨时间线的关联问题
- 覆盖场景：季节性主题汇总、地点重复出现、风格演变趋势

## 3. 数据需求

### 3.1 数据来源

- **个人摄影作品**：用户自己拍摄的照片，用作核心素材（检索、问答、分析），**不上传 GitHub**
- **真人短片截图**：无版权真人超短片截图（辅助展示），展示 VLM 对真人场景的识别能力，可公开

### 3.2 数据预处理

- 系统对原始照片进行批量视觉描述生成（VLM），输出结构化描述数据
- 用户以 Markdown 表格形式提供时间线描述，系统按 EXIF 拍摄时间自动匹配活动标签
- 照片元数据（路径、描述、时间线标签、EXIF 信息等）持久化到本地数据库
- 描述数据同步到向量知识库，用于语义检索
- 所有照片先经预处理生成描述，服务运行阶段不再实时调用 VLM

### 3.3 关于人物识别的决策

**本项目不做人物身份识别。** 照片中出现的人物统一以"有人""人物特写""人群"等通用描述处理，不做具体身份区分。原因：亲友相貌相似，提高识别准确率需要大量工程投入，且这不是产品核心场景。

## 4. 非功能需求

### 4.1 性能

- 单次查询响应时间：< 5 秒（含 AI 推理）
- 图片处理（单张视觉描述）：< 10 秒
- 并发：单机单用户，无需考虑高并发

### 4.2 可用性

- Web UI 交互友好，响应式布局，支持深色主题
- 上传支持拖拽，冲突检测提供对比预览
- 对话界面支持 Markdown 渲染（含图片），AI 回复标注查询类型
- 错误信息清晰，引导用户修复
- VLM 预处理和向量索引支持断点续传（队列中断后可恢复）

### 4.3 可扩展性

- 模型可切换：支持多种 AI 模型供应商
- 向量库可替换：预留替换接口
- 存储可扩展：本地文件 → 对象存储（预留接口）

### 4.4 安全

- API Key 不硬编码，通过配置文件管理
- 个人照片不上传 GitHub，通过 `.gitignore` 保护

## 5. 交互设计

### 5.1 Web 前端（主要交互方式）

- **照片管理**：网格展示照片缩略图，支持按时间线、日期范围、文件名筛选，按拍摄时间、导入时间排序。点击查看 EXIF 详情和 AI 描述。支持单张和批量删除。上传支持拖拽，冲突检测提供覆盖/跳过/保留两份三种策略
- **AI 对话**：会话式聊天界面，支持多轮对话追问。AI 回复标注查询策略类型，引用的照片可点击预览。每条回复可一键保存为评估用例
- **选题建议**：历史列表按时间倒序展示，可展开查看详情（叙事角度 + 照片序列），支持五星评分和删除。AI 一键生成新一批选题建议
- **聚类浏览**：自动发现的照片组合按视觉连贯性排序，支持 AI 生成主题标签和标题质量评估
- **队列管理**：VLM 预处理和向量索引均支持批量队列，前端实时显示进度

### 5.2 CLI（开发/演示入口）

命令行界面保留作为开发和演示的辅助交互方式，支持交互式对话、API 服务启动、评估运行等模式。

## 6. 风险与假设

### 6.1 风险

- **VLM 描述不准确** → 检索效果差：结构化属性提取作为补充维度，组合查询提高精度
- **API 费用过高** → 开发成本超支：使用低价模型，控制调用频率
- **向量检索召回率低** → 用户体验差：组合查询（结构化过滤 + 语义检索）提升精度，断层过滤去除低相关结果
- **属性值中英文不匹配** → 过滤返回空结果：动态获取数据库实际值，AI 仅使用存在的值

### 6.2 假设

- 用户能提供图片存储根目录路径
- 用户能编写 Markdown 格式的时间线描述文件
- 云端 API 在国内可稳定访问（或用户有代理）
- 单张图片大小 < 5MB（VLM API 限制）

## 7. 产品目标

### 已达成

- 系统完整可运行（初始化 → 导入 → Web 管理 → AI 对话）
- 照片 AI 描述覆盖率 100%
- 时间线标签覆盖率 100%（按 EXIF 自动匹配）
- Web 照片管理（上传、浏览、筛选、排序、搜索、删除）
- AI 对话支持四种查询策略（结构化、语义、工具、组合）
- 选题建议主动推送（AI 提案 + 用户审阅打分）
- 相似照片聚类 + AI 主题标签

### 待实现

- 检索准确率量化评估和持续监控
- 多轮对话上下文感知（指代消解、条件追加）
- 摄影报告生成（年度总结、风格分析）
- 发布历史分析（主题分布、频率、缺口识别）
- 系列感维护（跨时间线对比和延续建议）

---

## 8. 后续方向

当前产品已覆盖照片库的核心闭环：导入 → 检索 → 选题 → 审阅。下一步重点：

- **对话体验升级**：多轮上下文感知，支持指代上一轮结果、叠加条件
- **策略层建设**：从"单次选题"到"账号级内容策略"，包括发布历史分析和系列感维护
- **量化评估**：建立检索准确率和选题质量的量化基线，数据驱动迭代

详细演进路线见 [docs/backlog.md](backlog.md)。
