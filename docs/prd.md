# Photo Agent - 产品需求文档

## 1. 产品概述

### 1.1 产品定位

Photo Agent 是一个面向**个人摄影爱好者**的 AI 媒体资产助手。它通过对摄影作品进行 AI 视觉描述、建立时间线与标签知识库、构建向量检索系统，让用户可以用**自然语言**与自己的照片库对话，实现智能检索、摄影档案问答和创作辅助。

> **一句话定义**：让你的摄影照片库"会说话"的 AI Agent。


### 1.2 目标用户

- **摄影爱好者**：积累了大量照片，靠文件夹和文件名难以快速定位特定作品
- **创作者**：想基于历史作品分析风格特点，获取拍摄建议
- **求职者（我自己）**：展示 AI Agent 应用开发能力

### 1.3 核心价值主张

| 痛点         | 传统方式             | Photo Agent 方案           |
| ------------ | -------------------- | -------------------------- |
| 找照片困难   | 翻文件夹、靠记忆命名 | 自然语言描述即可检索       |
| 作品信息分散 | 拍摄时间、地点、主题散落在各文件夹 | 统一知识库，随时问答   |
| 创作灵感枯竭 | 孤立思考             | Agent 基于历史作品激发思路 |
| 风格认知模糊 | 凭感觉               | Agent 基于数据分析风格特点 |

## 2. 功能需求

### 2.1 功能优先级

```
P0 (MVP 必须): 智能检索 + 摄影档案问答
P1 (展示价值高): 摄影主题分析与创作建议
P2 (加分项): 个人摄影风格知识库 + 时间线关联分析
```

### 2.2 P0 - 智能检索

**用户故事**：

> 作为摄影爱好者，我想输入"2024 年在云南拍的雪山人像"，系统能返回匹配的照片列表和文字说明。

**功能描述**：

- 用户通过 CLI/API 输入自然语言查询
- Agent 理解查询意图（时间、地点、主体、风格等多维度），将其转化为向量检索
- 返回 Top-K 匹配图片（路径 + 描述文本 + 匹配度）
- 支持多轮对话细化检索条件（如"上一个结果里，我只要有人的"）

**验收标准**：

- [ ] 输入"海边的日落照片"，返回相关图片，准确率 > 70%
- [ ] 输入"2024 年云南旅游的森林照片"，返回匹配照片，附带时间和地点信息
- [ ] 输入"找每年的生日收到的礼物（3 月 7 号前后）"，返回历年相关照片
- [ ] 支持中文自然语言查询

### 2.3 P0 - 摄影档案问答

**用户故事**：

> 我想问"我拍过几次海边日出？都在哪些地方？"，Agent 能基于照片库回答。

**功能描述**：

- 用户提供图片存储的根目录，程序递归遍历所有图片文件，不约束用户的目录组织方式
- AI 生成每张照片的视觉描述
- 用户提供时间线描述文件（Markdown 表格格式：时间/活动/like/post），程序解析后根据照片 EXIF 拍摄时间匹配对应的活动名称
  - 例如时间线记录”2026-02-01 ~ 2026-02-05 云南旅游”，则该时间段内拍摄的所有照片时间线均为”云南旅游”
  - 支持单日、日期范围（`~` 分隔）、月份精度等多种时间格式
- 用户可就作品档案提问，Agent 基于知识库回答
- 支持追问和澄清

**进阶扩展**（后续迭代）：
- 根据文件名/大小/md5 识别重复文件，避免重复处理

**验收标准**：

- [ ] 提问"我拍过多少次雪山"，Agent 正确回答并列出相关照片
- [ ] 提问"2024 年我去过哪些地方拍照"，Agent 基于时间线标签回答
- [ ] 支持"我的人像片和风光片各有什么特点"这类对比问题

### 2.4 P1 - 摄影主题分析与创作建议

**用户故事**：

> 我想和 Agent 讨论"今年生日想送什么礼物"，Agent 能基于历年 3 月 7 日前后的照片提供建议。

**功能描述**：

- 用户提出主题或创作方向
- Agent 检索相关历史作品（时间线、主题、风格）
- 基于素材生成分析建议、拍摄方案
- 输出纯文本（不生成图片/视频）

**验收标准**：

- [ ] 输入"分析我 2024 年云南系列的风格特点"，Agent 给出基于实际照片的分析
- [ ] 输入"今年生日送什么礼物好？"，Agent 基于历年 3 月 7 日前后的照片给出建议
- [ ] 建议中引用具体历史作品（如"参考 2024-02-云南/IMG_0234.jpg 中的构图方式"）

### 2.5 P2 - 时间线关联分析

**用户故事**：

> 我想了解"我每年春天都拍了什么主题"，Agent 能做跨时间线的关联分析。

**功能描述**：

- 基于全部素材的描述和时间线标签
- Agent 能回答跨时间线的关联问题
- 如季节性主题、地点重复出现、风格演变等

**验收标准**：

- [ ] 提问"我每年春天都拍什么"，Agent 给出跨年份的主题汇总
- [ ] 提问"我拍海边的照片有什么变化"，Agent 分析不同时期的风格差异

### 2.6 P2 - 个人摄影风格知识库（已降级/可选）

**用户故事**：

> 作为展示用途，Agent 能总结我的摄影风格特点。

**功能描述**：

- 基于全部素材的描述，Agent 能回答宏观问题
- 如风格特点、常用构图、色调偏好、主题分布等

**验收标准**：

- [ ] 提问"我的摄影风格是什么"，Agent 给出基于素材的总结

## 3. 数据需求

### 3.1 数据来源

| 数据类型      | 来源                 | 用途               | 公开性            |
| ------------- | -------------------- | ------------------ | ----------------- |
| 个人摄影作品  | 用户自己拍摄（约 300 张精选） | 核心素材：检索、问答、分析 | **不上传 GitHub** |
| 真人短片截图  | 无版权真人超短片（辅助展示） | 展示 VLM 对真人场景的识别能力 | 可公开 |

> **为什么不使用动漫/影视素材？**
>
> 前期考虑过使用 Blender 开源短片（如《Sintel》）作为展示数据集，但最终决策全部使用真实摄影素材。原因见 [readme.md](../readme.md) 中的"数据集决策讨论"。

### 3.2 数据预处理

**照片导入流程**（Go 后端全栈，零 Python）：

1. 用户将原始照片放入任意目录结构（如硬盘上的照片文件夹）
2. 运行 `batch_vlm` 工具预处理：
   - 递归扫描所有图片，调用 VLM 生成视觉描述
   - 自动压缩超大图片（ImageMagick），压缩后的 JPG 直接存入 `data/photos/` 作为最终存储文件
   - 输出 `descriptions.json`（路径 → 描述映射）
3. 用户编写时间线描述文件（Markdown 表格），配置 `storage.timeline_path`
4. 启动 server，调用导入 API 扫描照片目录：
   - 读取 EXIF 拍摄时间
   - 根据拍摄时间匹配时间线文件中的活动名称
   - 从 `descriptions.json` 读取预生成的描述
   - 保存元数据到 SQLite（照片路径、描述、时间线标签、拍摄时间等）
   - 可选：同步写入 Dify 知识库

**工作流约束**：
- 所有照片必须先经 `batch_vlm` 预处理，server 导入时不再实时调用 VLM
- 时间线标签完全来自用户提供的 md 表格，不依赖文件夹命名

### 3.3 数据量级预估

- 个人摄影作品：约 200-300 张（精选好片）
- 真人短片截图：约 20-30 张（辅助展示，可选）
- 总素材量：< 500 张，Chroma 完全可承载

### 3.4 关于人物识别的决策

**本项目不做人物身份识别。**

原因：
1. 亲友相貌相似，提高识别准确率需要大量工程投入
2. 这不是展示 AI Agent 能力的核心场景
3. 用户明确表示"不需要识别是谁"

照片中出现的人物将统一以"有人""人物特写""人群"等通用描述处理，不做具体身份区分。

## 4. 非功能需求

### 4.1 性能需求

- 单次查询响应时间：< 5 秒（含 LLM 调用）
- 图片处理（单张视觉描述）：< 10 秒
- 并发：无需考虑，单机单用户使用

### 4.2 可用性需求

- CLI 交互友好，支持 Rich 美化输出
- 错误信息清晰，引导用户修复
- 支持断点续传（图片处理中断后可恢复）

### 4.3 可扩展性需求

- 模型可切换：支持 GPT-4o / Qwen-VL / Kimi 等
- 向量库可替换：Chroma 接口抽象，后续可换 Milvus
- 存储可扩展：本地文件 → MinIO / OSS（预留接口）

### 4.4 安全需求

- API Key 不硬编码，通过环境变量配置
- 个人照片不上传 GitHub，通过 `.gitignore` 保护

## 5. 交互设计

交互通过 Dify Web UI 完成。用户输入自然语言描述需求，Agent 自动选择知识库检索或调用工具查询，返回照片列表和文字说明。详细操作流程见 [DIFY_SETUP.md](DIFY_SETUP.md)。

## 6. 风险与假设

### 6.1 风险

| 风险             | 影响         | 应对措施                                               |
| ---------------- | ------------ | ------------------------------------------------------ |
| VLM 描述不准确   | 检索效果差   | 通过时间线标签做上下文增强，人工审核关键描述           |
| API 费用过高     | 开发成本超支 | 使用 GPT-4o-mini / Qwen-Turbo 等低价模型，控制调用频率 |
| 向量检索召回率低 | 用户体验差   | 混合检索（向量 + 关键词 + 时间线标签），支持人工标签   |
| 一周时间不够     | 功能做不完   | 严格按 P0/P1/P2 优先级，P2 可舍弃                      |

### 6.2 假设

- 用户能提供图片存储根目录路径
- 用户能编写 Markdown 格式的时间线描述文件
- 云端 API 在国内可稳定访问（或用户有代理）
- 单张图片大小 < 5MB（VLM API 限制）
