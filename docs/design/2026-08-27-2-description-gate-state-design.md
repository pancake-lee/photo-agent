# 描述质量闸门状态去滞后设计

> 状态：已完成。实时描述质量结论已通过用户 Web 验收与自动验证，详见专题中枢。
> 专题中枢：[AI 照片资产质量闭环中枢](2026-08-26-4-ai-asset-quality-loop-hub.md)。

## 1. 背景

`DSC_0054.jpg` 的当前 AI 描述可通过本地质量规则，批量 VLM 审查也将其判为正常；但照片行仍保留数据库迁移时写入的“历史描述未经过质量闸门”状态。Embedding 准入、批量 Embedding 审查和详情操作读取这个历史状态，于是把正常照片错误隔离。

根因不是描述或向量本身错误，而是“质量规则的即时结论”和“曾经保存的质量结论”同时充当准入依据，且两者没有统一的失效与刷新机制。

## 2. 设计目标

- 同一份当前描述在批量 VLM 审查、详情页、Embedding 准入和批量 Embedding 审查中始终得到同一结论。
- 打开批量审查不调用模型、不消耗 Token，也不因审查本身留下滞后的质量结果。
- 保留真正需要跨进程保存的 Embedding 处理结果和描述版本一致性；不再让历史迁移标记阻断正常照片。
- 现有确实命中质量规则、VLM 调用失败和 Embedding 失败的异常提示及检索隔离继续有效。

## 3. 当前方案

所有读取路径都对当前描述执行同一套本地校验：批量 VLM 候选、详情展示、Embedding 单张/批量准入均以该结论决定是否可继续。质量校验不保存“通过/未通过”的历史结论；只有 VLM 调用、Embedding 写入及描述版本仍保存处理状态和结果。

首次升级时，对已有照片做一次无 Token 的状态对齐：解除旧的“历史描述未经过质量闸门”标记，保留其 Embedding 是否需要重建的真实结论；读取时仍会隔离当前规则判为异常的描述。

## 4. 交互与数据边界

无论采用哪一方案，用户看到的交互保持不变：

- 批量 VLM 审查只列出无描述和当前规则判为异常的描述。
- 批量 Embedding 审查只列出当前描述可信、但没有向量、向量失败或描述版本已变化的照片。
- 详情页不再对仅因“历史描述未校验”而产生的警告展示“重新校验”；若当前规则确实不通过，仍展示原因和重生成入口。

持久化数据只承担处理事实：描述版本、Embedding 是否成功及其对应版本、调用/处理失败原因和履历。质量规则对当前文本的判断是可即时重算的派生结论，不把迁移时的结论作为长期业务事实。

## 5. 验收标准

- `DSC_0054.jpg` 当前描述通过规则时，不再显示“历史描述未经过质量闸门”，可出现在批量 Embedding 的候选中并可直接重建向量。
- 任意照片的 VLM 审查、Embedding 审查、详情页和队列准入对当前描述的质量结论一致。
- 当前描述命中故障画面/测试图规则时，仍会被 VLM 和 Embedding 同时隔离。
- 仅打开或刷新批量审查不调用 VLM，也不因本地审查改写照片质量结论。

## 6. 实现状态

- ✅ Go 照片详情与列表从当前描述即时派生 VLM 和整体健康结论；批量审查使用同一结论并显示即时原因。
- ✅ Python Embedding 队列以 Go 返回的即时 VLM 状态准入，名称与日志明确为“当前描述质量闸门”。
- ✅ 数据库迁移清除旧的历史质量提示，保留 stale 向量进入重建候选。
- ✅ 详情页仅在当前描述确实待复核时显示“重新校验”。
- ⏳ （用户）重启后端使迁移生效，打开 `DSC_0054.jpg`，确认不再显示历史警告，并在批量 Embedding 审查中确认其可重建向量。
