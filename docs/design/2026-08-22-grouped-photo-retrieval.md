# 组图检索

> 让向量检索和选题建议感知连拍组，以组为单位返回结果，避免连拍照片在检索中互相挤占。

---

## 1. 需求背景

连拍分组功能已上线（v1.0.10），系统将相似照片按精细和模糊两档归入连拍组。当前向量检索仍以单张照片为单位，一个 20 张的连拍组在向量库中占据 20 条记录。随着照片规模增长，这会导致：

- **检索偏差**：同组照片的向量高度聚集，检索时密集的向量簇压倒性地占据前排，掩盖其他主题
- **展示冗余**：检索结果返回大量几乎一样的照片，用户需要在相似图片中反复挑选
- **信息密度低**：LLM 在后续处理中反复读取高度雷同的描述文本

---

## 2. 设计目标

- 向量检索支持三种粒度：全量照片、精细连拍组、模糊连拍组
- 连拍组粒度下，仅封面图代表整组参与向量检索，大幅减少冗余
- 检索结果以组为单位展示，用户可展开查看组内全部照片并选择
- 现有全量检索行为不受影响

---

## 3. 用户交互流程

### 3.1 检索粒度选择

用户在聊天界面的输入区域上方选择检索粒度（单选）：

- **精确检索**（默认）— 以单张照片为单位检索，返回具体照片
- **精细连拍组检索** — 以精细连拍组为单位检索，每组返回封面图代表
- **模糊连拍组检索** — 以模糊连拍组为单位检索，每组返回封面图代表

粒度选择在整个会话中保持，直到用户主动切换。

### 3.2 结果展示

- **精确检索**：与现有行为完全一致，返回单张照片，点击查看详情
- **连拍组检索**：每条结果对应一个连拍组
  - 展示封面图缩略图
  - 卡片下方标注"共 N 张"
  - 点击封面图打开组内浏览弹窗（复用现有 BurstGroupModal），展示组内全部照片
  - 用户可从组内选择最满意的一张

### 3.3 选题建议

选题建议管线的 RAG 扩展选片阶段暂不受影响，仍使用全量照片检索。未来可考虑使用连拍组粒度提升选题的组间多样性。

---

## 4. 概念级数据关系

- 现有数据模型已支持连拍组：照片表包含两档连拍组关联字段，连拍组表记录封面图和照片数
- 前端已具备连拍组浏览基础：组内弹窗、封面角标、折叠视图、档位切换
- 向量库层面：当前只有一个向量集合存储全量照片描述。需新增两个集合分别存储精细和模糊连拍组的封面图描述
- 封面图同时存在于全量集合和对应的组集合中，保证任何粒度下都能被检索到

---

## 5. 关键设计决策

- **三个独立向量集合**：全量、精细组、模糊组各自独立。检索场景不同、互不影响、未来可独立调优
- **封面图双写**：封面图的描述同时存在于全量集合和组集合，保证全量检索不受影响
- **用户显式选择粒度**：由用户在界面切换，不由 AI 自动判断。降低分类错误风险
- **连拍组重建后需重新嵌入**：组结构变化后，用户通过"强制重新嵌入"更新组集合

---

## 6. 验收标准

- [x] 三种粒度可切换，各返回对应层级的结果
- [x] 连拍组粒度下，结果展示封面图 + 组内照片数
- [x] 点击封面图可展开查看组内全部照片
- [x] 全量检索行为不受影响
- [x] 删除照片后各集合中对应数据均被清理
- [x] 连拍组重建后，强制重新嵌入可正确更新组集合
