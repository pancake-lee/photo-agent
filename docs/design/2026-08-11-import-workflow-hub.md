## 1. 专题总览

- **问题一句话**：给 Windows 用户一个桌面入口，把「相机拍摄后导入照片库」这件原本手动的事（建目录、比对、迁移 NEF、上传）串成三步引导流程。
- **核心矛盾**：文件处理（本地扫描/EXIF/复制）需要本地能力，上传需要服务端能力，而浏览器既读不了本地文件、服务端又无 CORS，只能由客户端 Go 承担中间角色。
- **解决方案概要**：Wails 桌面应用（Go + Vue3）内嵌现有前端，新增 `#/import` 三步流程；服务端新增 NEF 存储与 storage/info；客户端 Go 承担扫描/比对/EXIF/复制/上传，经 Wails 绑定暴露给前端。

## 7. 设计决策记录

- NEF 仅存储不处理（不压缩/VLM/Embedding），服务端入库时读 EXIF
- 中转目录嵌套结构 full/like/nef 各建归档子目录 `YYYYMM-活动名`（`-` 分隔符）
- 执行阶段仅复制不删除，NEF 删除交还用户
- 全链路保留原始时间戳，不用拍摄时间覆盖修改时间
- storage/info 扫描 PhotoSrc（与上传落盘同源），消除 StorageRoot 分叉
- 上传重试从简：自动重试仅 1 次固定等待，持续失败交由用户手动「开始同步」+ skip 模式重试
- 收尾不删文件：程序只给文本建议，且限定本次归档子目录，不涉及中转根目录整体
