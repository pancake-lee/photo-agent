# 主题发现优化：从"共享属性选片"到"编辑视角提案"

> 状态：已实现
> 触发：2026-07-27，用户人工评估发现选题建议的输出效果"不够精彩"

---

## 1. 思考起点

### 1.1 问题发现

2026-07-26 的 Harness 设计讨论中首次记录了这个问题（见 [2026-07-26-harness-design.md](2026-07-26-harness-design.md) 的「优化：补上用户视角」段），当时作为评估模式需要改进的案例提出：

> 主题发现是一个 AI 驱动的创意策划功能，帮用户从照片库中自动"挖出"一组有发布潜力的照片组合，并为这组照片配上一个可执行的叙事角度。它不同于聚类（按相似度分组），也不同于标签生成（给组起名），它的输出是一份包含"照片组合 + 选题角度"的选题提案，直接回答"我可以发什么"的问题。
>
> 但是设想一下，这个功能是要做什么呢？这个功能是为了去发现我们平时在图库里面没有轻易看到的角度。而把当前连续拍摄的多张同场景下相似度高的照片组合起来，这件事情是每次我们拍摄活动结束后就会自然地去进行的事情，并不需要 AI 帮我们额外处理。

当时为了先跑通 Harness 闭环测试，这个问题被标记为"延后处理"。2026-07-27 实际使用主题发现功能后，确认了这个问题的严重性，决定作为正式需求对待。

### 1.2 问题定性

这是一个**效果问题**（功能能跑但输出不够好），而非缺陷。需要从方案层面重新设计，不是参数/阈值调整能解决的。

---

## 2. 讨论过程

### 2.1 根因分析

当前 `suggest.py` 的三个发现维度都遵循同一个范式：**按共享属性值匹配照片**。

| 维度 | 选片逻辑 | 典型产出 |
| --- | --- | --- |
| high_freq_ungrouped | 高频属性值 → 取匹配该值的 top 15 | 同场景连续拍摄的照片 |
| temporal_pattern | 某月份高频属性 → 取该月份匹配照片 | 同年同月同场景的照片 |
| scarce_quality | 稀有属性值 → 按质量分排序 | 同一次特殊拍摄的照片 |

摄影师天然会在同一场景连续拍摄多张相似照片，共享同一组属性值。按属性值匹配选片，**必然选中同一次拍摄的相似照片**。LLM 只能基于收到的候选生成标题和角度，它没有机会看到不同上下文之间的潜在连接。

核心矛盾：**算法在找"共同点"，但选题发现的价值在"对比/连接"**。

### 2.2 方案讨论

讨论了三个方向的方案：

#### 方案 A：在现有维度上加多样性约束（轻量）

在选片阶段增加过滤：同一日期最多选 N 张、优先选不同子属性的照片、按时间跨度加分。同时调整 prompt，引导 LLM 关注叙事角度而非简单归类。

- 利：改动小，风险低
- 弊：底层范式未变，仍是在"共享属性"框架内优化，难以产出真正有惊喜感的跨上下文选题

#### 方案 B：新增跨上下文发现维度（中等）

在现有三维度基础上，增加显式寻找跨上下文模式的维度，如属性迁移（同一主体出现在不同场景）、对比叙事（同一维度下的对比值）。

- 利：直接命中设计意图；与现有维度共存，不破坏已有逻辑
- 弊：需要定义跨上下文模式评判标准，实现复杂度中等

#### 方案 C：两阶段 LLM 策展（重量）

第一阶段产出创意简报，第二阶段让 LLM 为每个简报从全库中策展多样化照片，第三阶段生成最终标题和角度。

- 利：最贴近"AI 像编辑一样提案"的产品愿景
- 弊：LLM 调用次数大幅增加，延迟和成本上升，LLM 策展的可控性较差

推荐方案 B，用户综合考虑后，在方案 B 和 C 之间发展出了自己的设计思路。

## 3. 设计思路

### 3.1 核心原则

避免输出"连续连拍组合"（用户已经会手动发朋友圈的素材），主动挖掘"用户没想到可以放在一起的照片组合"，让 AI 像编辑一样先"想角度"再"选照片"。

### 3.2 三阶段工作流

#### 阶段一：随机种子 → 主题直觉

从图库中随机采样 6–9 张照片（覆盖不同时间、场景、属性），交给 LLM 以编辑视角浏览，输出初始主题观察——无需使用所有照片，只需从中获得灵感。目的是引入偶然性，打破"共享属性优先"的惯性。

LLM 收到的提示中不包含拍摄日期信息（避免 LLM 按时间线归类），只看视觉内容。

#### 阶段二：主题 → 扩展选片

围绕第一阶段生成的主题方向，调用 RAG 从全库检索语义相关照片，同时按多样性约束采样（限制同一日期/场景/属性的最大数量），使候选照片在语义相关的同时保持多样性。

#### 阶段三：主题沉淀 → 完整选题提案

将选片结果连同照片描述再次交给 LLM，生成结构化的选题提案——包含选题标题、叙事角度、推荐照片序列、发布理由。照片顺序按叙事逻辑排列，不按时间或相似度排列。

### 3.3 关键实现要点

#### 随机采样的合理性

随机采样并非"放弃控制"，而是为了引入 LLM 自身不会主动探索的组合路径。统计聚合只会返回高频属性值，而随机采样覆盖了低频组合，允许 LLM 在不同上下文中发现跨连接线索。

#### 多样性约束的位置

第一阶段不约束多样性（随机已分散），第二阶段在 RAG 检索后进行多样化采样（同一日期/场景/属性至多取 1–2 张），确保最终选片数量可控、视觉叙事多样。

#### 与现有 P2 聚类的区别

聚类按向量相似度分组，输出静态分类；本设计以随机种子引发随机主题，输出动态选题提案。两者并存，服务不同场景。

### 3.4 与现有 suggest.py 的关系

现有三个维度（高频未成组/时间线规律/稀缺优质）作为本方案的**备选输入**：如果阶段一随机采样未能产生足够主题，可回退到现有维度产出的候选作为补充。

### 3.5 工作流总览

```text
随机采样 6-9 张 → LLM 生成主题直觉（不暴露日期信息）
    → RAG 按主题检索候选照片 → 多样性采样过滤
    → LLM 沉淀完整选题提案（标题 + 角度 + 照片序列 + 理由）
```

### 3.6 验收标准

- [x] 选题提案中至少包含 5 张照片 — ✅ 3 条提案均为 5-6 张
- [ ] 照片时间跨度 > 7 天（不来自同一连续拍摄会话） — ⚠️ 1/3 不满足：「水边的独白」仅约 22 小时；约束仅在日志中输出，未强制执行
- [x] 叙事角度描述可被理解为有发布价值 — ✅ 三条提案均有编辑视角叙事
- [ ] Stage 3 LLM 返回的 photo_id 经过数据库校验 — ❌ 已证实幻觉 1 次（UUID 截断），见 B8
