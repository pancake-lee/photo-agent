# 已选照片列表控件（SelectedPhotoList）设计

> 中枢文档：[2026-08-26-3-photo-selection-controls-hub.md](2026-08-26-3-photo-selection-controls-hub.md) — 本专题全部关联产物的汇总入口

## 1. 需求背景

应用内多处功能需要「展示用户已选的照片并允许继续编辑」，目前各写各的：

- 图文工坊：卡片网格 + 连拍组展开精选 + 拖拽排序，能力最全，但是页面内联实现，别处用不上
- 黄金用例新建弹窗：行内小缩略图列表，样式与图文工坊不一致，且没有连拍组语义
- 主题发现详情、聚类详情等另有只读小缩略图行（PhotoThumbList），定位为纯展示，与本控件不冲突

用户决策（2026-08-26）：把图文工坊的已选照片展示样式确立为全应用统一的「控件2」，
黄金用例新建页率先接入；粒度不再人工编辑，完全由选图时的连拍展示级别自动推导。

## 2. 控件定位与功能描述

控件2 是「已选照片的展示与编辑」控件，回答一个问题：**用户选完照片之后，看到什么、还能做什么**。

核心能力（用户视角）：

- **卡片网格展示**：正方形图片卡片（复用图片管理的照片卡片样式），下方显示文件名；
  与图片管理列表的视觉语言一致，用户无需重新学习
- **连拍组条目**：一个连拍组在列表中是一张封面卡片，带「×N」角标标识组内照片数；
  点开弹出连拍组弹窗，可浏览组内成员
- **连拍精选**：在连拍组弹窗中勾选一或多张成员，确认后组条目被替换为选中的单张照片条目
  （语义：这个组我只想要这几张）
- **移除**：任一条目（单张或整组）可单独移除
- **拖拽排序**（可选开启）：调整照片顺序，顺序对发起方有意义时使用（如图文工坊的成帖顺序）
- **预览**：点卡片图片可发起大图预览，预览行为由发起方决定

与控件1（选图覆盖层）的衔接：控件1「完成选择」回传选中的照片（含自动推导的粒度与连拍组信息），
发起方将其交给控件2 展示；用户在控件2 里精选连拍组后，组退化为单张。

## 3. 用户交互流程

以黄金用例新建为例：

1. 用户在新建弹窗点「选择照片」→ 进入控件1 覆盖层，勾选若干照片/连拍组封面 → 完成选择
2. 回到弹窗，已选区域以卡片网格展示：单张照片是普通卡片；折叠视图下勾选的连拍组是带 ×N 的封面卡片
3. 用户点连拍组卡片 → 弹出组浏览弹窗（curate 模式）→ 勾选想要的成员 → 点「连拍精选」→
   组卡片被替换为选中的单张卡片
4. 用户可悬停任一卡片点移除按钮删除；点卡片图片预览大图
5. 保存时，单张卡片按单张粒度持久化，仍是组的卡片按组粒度持久化（封面 + 粒度档位）

## 4. 概念级数据关系

条目分两类：

- **单张条目**：一张照片（标识、文件名、后端主键引用）
- **连拍组条目**：封面照片 + 所属分组档位（精细/模糊）+ 组内成员集合（打开时才加载，加载后常驻）

持久化时连拍组只保存「封面 + 粒度档位」一条引用（与黄金用例现有粒度模型一致），
不展开保存全部成员；从持久化数据还原组条目时，按档位现查组信息与成员。

## 5. 关键设计决策

- **复用图文工坊样式为母体**：它是唯一已验证的「卡片 + 连拍组 + 精选」完整实现，
  抽取为独立控件而不是重新设计，降低回归风险
- **粒度自动推导，UI 不暴露粒度编辑**：粒度语义（单张/细组/粗组）对用户是负担，
  选择连拍组封面这个动作本身就表达了组粒度意图；精选动作天然表达「退化为单张」。
  数据层仍保留粒度字段，评估与检索后端依赖它
- **成员懒加载**：组条目创建时只需封面，首次打开弹窗才拉成员，避免选几十个组时的批量请求
- **发起方特有语义放在发起方**：控件只提供通用编辑能力；粒度持久化口径、排序是否启用、
  预览行为等由各发起方决定

## 6. 验收标准

- [x] 黄金用例新建：选照片后以卡片网格展示，连拍组显示 ×N，点开可精选、可移除
- [x] 粒度自动推导：勾组封面得组粒度，精选后变单张粒度，保存后评估口径与改造前一致
- [ ] 图文工坊（若回迁）：添加照片、连拍精选、拖拽排序、移除、保存草稿行为与改造前一致
