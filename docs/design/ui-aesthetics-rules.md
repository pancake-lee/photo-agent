# UI 美学规则

> AI 生成前端代码时参考的基础视觉设计原则。面向非设计师，每条规则可操作、可验证。
> 来源：Photo Agent 前端开发迭代中暴露的视觉问题归纳。

---

## 一、布局：就近原则

**规则 1.1**：功能和它所影响的数据放在同一行或同一区块内，不要让用户视线在远距离元素之间跳转。

反例：评估摘要放在独立工具栏行，和统计卡片隔了 40px，用户需要上下对照。
正例：评估摘要直接嵌入统计卡片行，靠右对齐，视觉上属于同一组。

**规则 1.2**：同一行内，左侧放数据展示，右侧放操作入口。用户从左到右读：先理解现状，再做操作。

```
[数据指标...]                              [操作按钮]
```

---

## 二、按钮：文案稳定，状态用视觉表达

**规则 2.1**：按钮文案描述"动作"，不应随数据状态变化。用户靠位置和图标识别按钮，文案一变就需要重新阅读。

反例：已生成标题时显示"重新生成"，未生成时显示"生成主题"，用户每次都要确认按钮功能没变。
正例：始终显示"生成标题"。是否已有标题通过按钮样式（primary/outline）区分，不靠文案。

**规则 2.2**：禁用态用视觉线索（灰色、降低透明度），不要隐藏按钮或改文案。用户需要知道"这个操作存在，只是当前条件不满足"。

反例：label 为空时不显示"评估标题"按钮，用户不知道这里缺少一个功能。
正例：始终显示"评估标题"，label 为空时按钮失灰，用户一看就懂。

---

## 三、数据展示：零值也要占空间

**规则 3.1**：数值型指标始终显示，无数据时显示零值（`0/0`、`—`），不隐藏组件。组件突然出现/消失会让用户困惑"这个位置是固定的还是动态的"。

反例：评估数据为空时隐藏"标题通过 X/Y"卡片，工具栏右侧空了一块。
正例：始终显示卡片，无数据时显示 `0/0`，用户明确知道"还没有评估过"。

**规则 3.2**：汇总指标放前面，详细数据放后面。用户先看"整体怎么样"，再根据需要展开细节。

正例：簇卡片中，先看到 `标题校验 2/4 通过` 标签，如果全通过则不展示详情区；有不通过的才展开看具体问题。

---

## 四、信息层次：先整体后细节

**规则 4.1**：每个区块按照"标识 → 摘要 → 详情 → 操作"的垂直顺序排列。

正例（簇卡片）：
```
标题文字 + 主题描述               ← 标识
[校验摘要] [照片数] [凝聚度] [操作按钮]  ← 摘要 + 操作
  └ 评估失败详情（仅在有失败时展开）  ← 详情
照片缩略图                         ← 内容
```

**规则 4.2**：操作按钮按作用范围从大到小排列。批量操作在汇总区，单条操作在条目内。

正例：工具栏中是「重新生成」「重新评估」（批量），簇卡片内是「生成标题」「评估标题」（单条）。

---

## 五、间距：同类聚合，异类隔离

**规则 5.1**：功能相关的元素之间用较小间距（8-12px），功能不相关的区块之间用较大间距（16-24px）。

反例：评估摘要和操作按钮紧挨在一起，两者功能和语义不同，看起来像一组。
正例：评估摘要（数据）和按钮（操作）之间留清晰间距。

**规则 5.2**：同一组标签使用相同的间距和对齐方式。不同组的间距应明显大于同组内的间距。

正例：`[标题校验 2/4 通过] [69 张] [凝聚度 87%]` 三个标签间距一致，与后面的按钮组之间间距更大。

---

## 六、颜色：意义一致

**规则 6.1**：同一颜色在同一页面中表达同一语义。不要在一个地方用绿色表示"成功"、另一个地方用绿色表示"普通信息"。

正例：绿色 tag = 全部通过，黄色 tag = 有警告/失败，蓝色 tag = 中性数据。

**规则 6.2**：警告色（黄/橙）用于"需要注意"，错误色（红）用于"需要修复"。不严重的问题用警告色而非错误色，避免过度报警。
