# 相机拍摄活动后的导入流程设计

设计一个 Windows 客户端，将承担两个角色：**文件处理引导工具** + **Photo Agent 的桌面入口**。最终它内嵌 Web 视图直接展示 Photo Agent 界面，而文件处理功能作为 Agent 的一个子模块存在。

## 文件夹结构设计（长期存储 + 中转）

**核心设计原则：所有照片按“月份 + 可选活动”组织，便于程序批量处理和人工浏览。**

```
服务器长期存储根目录/
├── 202608/                         # 月份目录（无活动时用）
│   ├── IMG_0001.JPG
│   ├── IMG_0002.JPG
│   └── ...
├── 202608_山西旅游/                # 月份 + 活动名称（有活动时用）
│   ├── IMG_0001.JPG
│   └── ...
├── 202609_城市街拍/
│   └── ...
└── 202609/                         # 随手拍
    └── ...
```

**对于文件清理阶段（full + like + nef）的中转目录结构**：

```
中转目录/
├── full/                           # 爱思助手导出全部 JPG
│   └── IMG_0001.JPG
├── like/                           # 爱思助手导出 Like JPG
│   └── IMG_0001.JPG
└── nef/                            # 用户预先放好的 NEF（复制来的）
    └── IMG_0001.NEF
```

客户端的职责是：比对 full 和 like 中的 JPG 文件名，决定哪些 NEF 应保留、哪些应删除，然后将结果拷贝到长期存储目录下对应的月份/活动目录中。

## 第一步：新建拍摄活动 — 引导与文件夹命名

**用户操作流程**：

1. 点击“新建拍摄活动”
2. 输入日期（默认当天，可修改，格式 `YYYYMM`）
3. 输入活动名称（可选。若为空，表示“随手拍”，仅按月份组织）
4. 输入中转目录路径（full/like/nef 所在位置）
5. 点击“确认”，客户端做三件事：
   - 在长期存储根目录下创建对应的月份目录（如 `202608`）或月份活动目录（如 `202608_山西旅游`）
   - 创建一个 `full/` 和 `like/` 的文件夹（用于用户存放导出文件）
   - 显示一段文字引导：
     - “请用爱思助手将 iPad 的【全部照片】导出到 `full/` 文件夹”
     - “请用爱思助手将 iPad 的【个人收藏】导出到 `like/` 文件夹”
     - “请把 SD 卡中对应的 NEF 文件复制到 `nef/` 文件夹（本次处理的照片对应的 NEF）”
6. 用户完成后，点击“我已准备好，进入下一步”

**需要注意的细节**：

- 随手拍（无活动名称）的照片同样按月归档，存放在 `202608/` 目录下，但不带活动标识
- 长期存储目录中，月份和活动是**父子关系**还是**平行关系**？建议采用**平行关系**，即 `202608/` 和 `202608_山西旅游/` 是同级目录。这样做的好处是：
  - 程序容易识别：目录名以“数字\_”开头的是有活动的，仅数字的是随手拍
  - 用户容易理解：活动文件夹包含活动名，随手拍文件夹仅包含月份
- 客户端在创建目录时，如果发现同名目录已存在，应提示用户“该月份/活动已存在，是否追加到此目录？”，避免重复创建

## 第二步：分析并执行清理 — 报告内容设计

用户完成文件导出后点击“下一步”，客户端开始分析并生成报告。

**报告应展示的信息**：

**总体统计摘要**（避免用户误删）：

| 项目                                              | 数量 |
| ------------------------------------------------- | ---- |
| full 中 JPG 总数（已导入 iPad 并保留）            | 245  |
| like 中 JPG 总数（用户点❤️的）                    | 12   |
| nef 中 NEF 总数                                   | 245  |
| 将在 iPad 中已删除、对应 NEF 被删除的数量         | 233  |
| 将在 like 对应 NEF 保留并迁移到 like 文件夹的数量 | 12   |

**时间分布信息**（用于检查是否混入其他活动的照片）：

- “本次处理的文件，时间范围：`2026-08-01` 至 `2026-08-15`”
- “⚠️ 发现 3 个文件日期不在本次范围内（`2026-07-20`），请确认是否误将其他活动照片放入”
- “⚠️ 发现 full 中 12 个 JPG 没有对应的 NEF 文件，请检查 NEF 是否已完整复制”

**操作明细**（可折叠展开，供检查）：

- 删除列表（按时间倒序排列）：`IMG_0001.NEF（2026-08-01）`，`IMG_0002.NEF（2026-08-02）`……
- 迁移列表：`IMG_0056.NEF（2026-08-05）`，`IMG_0057.NEF（2026-08-05）`……

**最终确认按钮**：

- “确认执行，迁移 NEF 到 like 文件夹，删除其余 NEF”
- 执行完后，清空 nef 文件夹（或移动到回收站，由用户选择是否彻底删除）

如果用户勾选“移动到回收站”而不是“彻底删除”，可增加一层安全保障，方便误删后找回。这是一个值得保留的选项。

## 第三步：上传到服务器 — 验证信息设计

**用户操作流程**：

1. 用户输入服务器存储根路径（如 `//192.168.1.100/photo_storage/`）
2. 点击“连接并验证”，客户端展示服务器当前状态：
   - 该路径下总文件数：`1,247 张 JPG，89 张 NEF`
   - 已有月份文件夹：`202608/ 202607/ 202606/`
   - 已有活动文件夹：`202608_山西旅游/ 202608_城市街拍/`
   - 本次将新增：`202608_山西旅游/`（12 张 JPG，12 张 NEF）
   - 上次同步时间：`2026-08-10 14:30`
3. 用户确认无误后，点击“开始同步”
4. 同步完成后，显示结果：
   - 上传成功：`12 张 JPG，12 张 NEF`
   - 耗时：`12.3 秒`
   - 确认后，清空中转目录（full/like/nef）或归档

**后续考虑**：如果服务器路径配置错误（如无权限、磁盘空间不足），客户端应能给出明确提示，例如“服务器磁盘空间不足 20GB，需要清理后再同步”。

## 下一步：Photo Agent 视角：如何使用这些照片

> 原来计划：这部分可以先不做设计，先确认上述流程跑通。后续客户端稳定后，再考虑以下可能的功能

当前已调整方向：**先让 Wails 客户端内嵌现有 Vue 3 前端，在 Web 中新增导入工作流子页面**。这样客户端统一入口，文件处理作为 Agent 的一个功能模块。JPG 上传后走现有处理管线（压缩→VLM→Embedding→ChromaDB），NEF 仅存储。

以下功能随 JPG 入管线自然获得：

- JPG 作为 VLM 输入源，生成描述、嵌入向量、存入 ChromaDB
- 结构化属性提取（色彩/光线/构图/情绪/主体）
- 按月份/活动自动生成检索维度（例如”2026 年 8 月山西旅游的夜景照片”）
- NEF 保留路径可在 Agent 中记录，方便用户后期调用外部工具（如 Lightroom）进行后期处理
- 归档状态标记（哪些已处理、哪些待处理）用于构建”待处理照片”队列

## 规划决策与实施方案

> 规划日期：2026-08-11

### 技术选型

- **Wails（Go + Vue 3）**：与现有技术栈一致，Go 原生处理文件操作，Vue 3 复用现有前端
- **服务端交互**：客户端通过 HTTP 调用现有 `POST /api/v1/photos/upload` 单张上传，客户端做有限并行
- **项目结构**：`client/` 目录放在现有 `photo-agent` 仓库
- **NEF 处理**：服务端只存储（记录路径+文件名），不压缩、不 VLM、不进 ChromaDB

### 架构

```
Wails 桌面应用（Windows 客户端）
├── Go 后端（客户端侧）                ← 新增 client/
│   ├── 文件系统操作：扫描目录、比对、读 EXIF、拷贝/删除
│   └── HTTP 客户端 → 调用服务端 API 上传
├── Vue 3 前端（WebView 内嵌）         ← 复用现有 web/
│   ├── 现有页面：照片管理、AI 对话、选题建议、聚类
│   └── 新增页面：#/import 导入工作流三步流程

服务端（Linux，现有）
├── Go 后端                           ← 新增：NEF 存储 + storage/info API
└── Python AI 服务（不变）
```

前端通过 Wails runtime 调用客户端 Go 做本地文件操作（扫描目录、读 EXIF 等），通过 HTTP 调用服务端 Go 做数据操作（上传、查询）。前端检测运行环境：在 Wails WebView 中显示导入工作流入口，浏览器中隐藏。

### DevTools 调试方案 ✅ (2026-08-12)

Wails 桌面应用内调试手段的选型与落地。

#### 右键 → 检查（Inspect）— 已解决

WebView2 的上下文菜单在检测到页面有文字被选中时，会包含"检查"（Inspect）选项，否则不显示。初期尝试在 `contextmenu` 或 `mousedown` 事件中临时创建零宽空格选区，但 WebView2 在 `mouseup`→`contextmenu` 之间会清除程序化创建的选区，导致不稳定。

**最终方案：持久幽灵选区（persistent ghost selection）**

核心发现：WebView2 只清除"本次右键序列中"创建的选区，不会清除上一次交互留下的选区。"双击右键"之所以稳定，正是因为第一次点击的选区残留到了第二次。

实现（`web/src/App.vue` onMounted）：

1. 维护一个 1×1px、`pointer-events:none` 的 span 元素（ghost），内含零宽空格
2. 页面加载时在 (0,0) 预置 ghost 并选中
3. 每次 `mousedown`：
   - 右键：始终将 ghost 移到点击位置并选中
   - 左键：仅在无真实选区时更新 ghost 位置（用户拖选文字时不干预）
4. `contextmenu` 兜底：万一选区仍被清除，最后补救一次
5. ghost 不清理，只更新位置，始终保持在 DOM 中

这样 ghost 始终是"上次点击留下的选区"，WebView2 不会清除它，右键菜单稳定包含"检查"。

#### 键盘快捷键（F12 / Ctrl+Shift+I）— 已放弃

尝试过的方案均无效：

- Wails `AcceleratorKeyCallback` 仅处理 `Ctrl+Shift+F12`，不响应 F12 或 Ctrl+Shift+I
- WebView2 `PutAreDevToolsEnabled(true)` 理论上应启用原生快捷键，实际不生效
- Go 层通过 `ICoreWebView2Settings::put_AreDevToolsEnabled` 同样无效
- 前端 `keydown` 监听无法触发原生 DevTools（JS 无权调用）

**放弃原因**：WebView2 的键盘快捷键由底层 Chromium 控制，Wails 的 Go API 和前端 JS 均无法接管或触发。当前右键 → 检查已稳定可用，投入产出比不支持继续深入。

> 如果未来必须支持快捷键，可能的探索方向：(1) 在 Wails Go 层注册全局热键（Windows API `RegisterHotKey`），收到热键后调用 WebView2 COM 接口 `OpenDevToolsWindow()`；(2) 等待 Wails v3 对 WebView2 设置的更完整暴露。

#### 阶段 2：服务端 NEF 存储 + 存储状态查询 API

在现有 Go 后端新增两个能力：NEF 文件上传（仅存储）、存储目录状态查询。

- 现有 `POST /api/v1/photos/upload` 增加对 NEF 的处理：识别 `.NEF` 后缀，跳过压缩/VLM/Embedding，直接存入对应月份/活动目录，写入 DB 记录（标记文件类型）
- `GET /api/v1/storage/info` — 返回存储根路径下总文件数（JPG/NEF）、已有月份文件夹、已有活动文件夹、上次同步时间
- 文件夹命名规则支持：`202608/`（随手拍）和 `202608_山西旅游/`（有活动）

#### 阶段 3：Wails Go 后端 — 本地文件操作能力

客户端 Go 层实现文件扫描、比对、EXIF 读取、拷贝/删除操作，通过 Wails 绑定暴露给前端。

- 扫描 `full/`、`like/`、`nef/` 三个中转目录，返回文件列表和计数
- 比对逻辑：like 中有同名 JPG 的 NEF 保留，仅 full 中有但 like 中无的 NEF 标记删除
- EXIF 读取：提取拍摄时间，检测时间范围异常（混入其他活动的照片）
- 文件操作：按确认结果执行拷贝（保留的 NEF 拷到中转 like 目录）、删除（其余 NEF）
- 所有操作通过 Wails 绑定暴露为 JS 可调用的函数

#### 阶段 4：前端导入工作流页面（#/import）

在 Vue 3 中新增路由和页面，实现三步流程的完整 UI。各步骤调用客户端 Go（Wails binding）或服务端 API。

**步骤 1 — 新建活动**

- 日期选择（默认当天，格式 YYYYMM）
- 活动名称输入（可选，为空则表示随手拍）
- 中转目录路径输入（full/like/nef 所在位置）
- 点击确认 → 调用客户端 Go：创建中转目录 `full/`、`like/`、`nef/`，显示文字引导（告知用户用爱思助手导出到对应文件夹）
- 用户完成后点击”我已准备好，进入下一步”

**步骤 2 — 分析报告**

- 调用客户端 Go 扫描三个目录 → 返回分析数据
- 展示统计摘要：full 中 JPG 总数、like 中 JPG 总数、nef 中 NEF 总数、将删除的 NEF 数、将保留的 NEF 数
- 展示时间分布：文件时间范围，异常日期警告，无对应 NEF 的 JPG 警告
- 操作明细：删除列表、迁移列表（可折叠，按时间倒序）
- 用户确认后执行：拷贝保留的 NEF、删除其余的 NEF、清空中转目录

**步骤 3 — 上传同步**

- 输入服务器地址（如 `http://192.168.1.100:10004`）
- 点击连接验证 → 调用 `GET /api/v1/storage/info` 展示服务器状态
- 展示本次将新增的内容
- 用户确认 → 客户端并行调用 `POST /api/v1/photos/upload` 上传 JPG+NEF
- 显示结果：成功数、失败数、耗时
