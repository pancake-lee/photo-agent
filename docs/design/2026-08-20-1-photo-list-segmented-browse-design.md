# 照片列表分段浏览设计文档

## 1. 需求背景

照片列表当前是「分页 + 统一方形缩略图网格」：

- `PhotoGrid` 用四列等宽网格排布，`PhotoCard` 以 1:1 裁切缩略图，布局整齐无空缺
- 默认每页 24 张，翻页是唯一浏览方式。照片库已 1400+ 张（连拍分组文档实测 1436 张），80+ 页难以定位到某个时间段
- 现有筛选只有「拍摄日期范围」手动选、「活动」「文件名搜索」，没有按时间或活动维度快速跳转的能力

目标：把照片列表改造成**分段浏览**，按拍摄时间或活动标签把照片流分段并插入分割线，右侧提供导航快速跳转，滚动加载替代翻页。

**库内数据实测**（2026-08-20 对 `data/sqlite/photo_agent.db`）：非 NEF 照片 1323 张，覆盖 16 个月份、23 个有活动标签的时间线；**无活动标签（散图）335 张，占 25%**；shot_at 零值 2 张。散图量级决定了「未分类」不能是导航里的二等公民，见第 6 节。

## 2. 功能目标

- 分割线：在照片流中按分段方式插入标题，帮助用户感知当前位置
- 右侧导航：按分段方式列出跳转目标，当前所处段落高亮，点击跳转
- 滚动加载：滚动到底自动加载下一页并追加，替代分页组件
- 三种分段方式：按天 / 按月 / 按活动，用户可切换
- 排序收敛：**移除「按文件名 / 按导入时间」排序及对应 UI**，只保留拍摄时间升/降序。分段浏览依赖照片流时间有序，收敛后该前提恒成立，排序 UI 从下拉框简化为升降序切换按钮（用户已确认）。后端 `sortBy` 参数与白名单保留不动，仅前端不再提供其他入口

## 3. 分段方式与导航维度

用户可在三种分段方式间切换，决定分割线和右侧导航的维度：

- **按天**：每天一条分割线，显示日期（如「2026 年 8 月 20 日」）
- **按月**：每月一条分割线，显示该月第一天日期
- **按活动**：按照片的 timeline（活动）标签分段，显示活动名称

右侧导航的跳转维度与分段方式对应：

- 按天 → 月份导航（降级，天数过多不适合做跳转列表）
- 按月 → 月份导航
- 按活动 → 活动导航

## 4. 交互定义

### 4.1 分割线

- 在照片流中按当前分段方式插入分割线
- 连拍组作为单卡片展示，分割线位于组卡片顶部，而非组内每张照片上方
- 连拍组展开/折叠不影响分割线位置

### 4.2 右侧导航

- 列出当前分段方式对应的跳转目标，按时间倒序（最新在上；活动按活动时间倒序）
- 当前所处段落高亮
- **点击跳转采用筛选重置式（用户已确认）**：
  - 目标段落已加载（在当前已拉取的照片流中）→ 直接锚点滚动到该段落第一条分割线
  - 目标段落尚未加载 → 以目标段落为筛选条件**重置列表**重新拉取，从目标段落开始渲染。按天/按月的月导航项跳转 = 设置 `shotAtStart/End` 为该月起止；按活动的活动导航项跳转 = 设置 `timeline` 为该活动
  - 重置式跳转后，原有的手动筛选条件（日期范围/活动/搜索）与跳转筛选叠加冲突时，跳转筛选覆盖对应维度。导航面板上提供「回到最新」项（清空跳转筛选恢复默认视图）
- 滚动到新段落时，导航高亮自动跟随
- 按天方式下导航降为月份：滚动到某月时高亮该月

### 4.3 滚动加载

- 滚动接近列表底部时自动加载下一页数据并追加，移除底部分页组件
- pageSize 从 24 调大到 100（后端单页上限即 100），减少加载次数；1323 张库全量约 14 次请求
- 加载更多时若跨越新段落，自动追加对应分割线（分组计算是响应式的，追加数据后分割线自然出现）

### 4.4 与连拍折叠的正交性

- 分割线基于实际渲染的照片计算，与「全部展开 / 精细折叠 / 模糊折叠」三级展示正交

## 5. 现状复用

- 列表接口 `photoServiceSearchPhotos` 是分页式的（page + pageSize，后端单页上限 100），滚动加载可继续复用，前端改为追加渲染（pageSize 调大到 100，1323 张库约 14 次请求可全量加载）
- `GET /photos/stats` 已返回 `monthly` 月份直方图（month + count，SQLite `strftime('%Y-%m')` 聚合，仅含有 shot_at 的照片），月份导航可直接复用
- `GET /timelines` 已返回活动列表（`timelineServiceListTimelines`，按 timeline.json 文件顺序排列），活动导航可直接复用；活动的时间排序可由该活动下照片的 shot_at 推导（前端从已加载照片推导，或跳转时直接用 `timeline` 筛选，无需后端新增接口）
- 照片已有 `shot_at`（拍摄时间）和 `timeline`（活动标签）字段，可作为分割依据
- **唯一后端改动**：`timeline` 筛选目前传空串等于不过滤，无法筛出「无活动标签」照片（库内 335 张散图）。约定 sentinel 值 `timeline="none"`，DAO 层翻译为 `timeline = ''` 过滤（svc 层 3 行翻译逻辑，proto/SDK 均不变）。用于按活动分段下「未分类」段落的导航跳转

## 6. 边界情况

- shot_at 为零值的照片（库内 2 张）无法归入天/月：置入「未知时间」段落，排在时间流末尾（升序在最后、降序在最前，与 SQL 排序 `shot_at DESC, imported_at DESC` 中零值实际落位一致）。该段落不进右侧导航（仅 2 张，不值得占位）
- 无活动标签的照片（335 张散图）：按活动分段时归入「未分类」段落，**排在活动段落之后**；导航含「未分类」项，点击跳转用 `timeline="none"` sentinel 筛选
- 筛选（日期范围 / 活动 / 搜索）生效时，导航保持全局列表、仅高亮当前可见段落（已采纳此倾向，筛选不收窄导航）
- 删除照片导致某段落清空后，导航列表随之更新（stats/timelines 重新拉取或本地计数递减）
- 切换分段方式后，右侧导航与分割线同步更新；已加载照片不重拉，仅重新分组计算
- 重置式跳转（4.2）后照片流从目标段落开始，上方段落不可向上滚动浏览（用户已知悉此交互取舍）；需要回到完整流点「回到最新」或清空筛选

## 7. 验收标准

- [ ] 分割线按天/月/活动三种方式正确插入
- [ ] 右侧导航列出对应跳转目标，当前段落高亮
- [ ] 按天方式下导航降为月份
- [ ] 点击已加载段落锚点滚动正确；点击未加载段落重置拉取正确
- [ ] 滚动加载追加照片，不再有分页组件
- [ ] 滚动时导航高亮自动跟随
- [ ] 连拍组展开/折叠不影响分割线位置
- [ ] 切换分段方式后导航与分割线同步更新
- [ ] 加载更多跨段落时自动追加分割线
- [ ] 「未分类」段落与导航项正常（timeline="none" sentinel 生效）
- [ ] 排序 UI 收敛为升降序切换，「按文件名/按导入时间」入口移除
- [ ] 「未知时间」段落（shot_at 零值）正常落位，不进导航
- [ ] 2000+ 张照片滚动流畅，切换分段方式响应迅速
- [ ] `pnpm build` 通过；后端 sentinel 过滤单测 PASS

## 8. 实施拆解

1. **后端 sentinel**（3 行级改动）：svc 层把 `timeline == "none"` 翻译为 DAO 层空值过滤 + 单测
2. **前端分段基础**：分割线组件 + 按分段方式分组计算（computed，基于已加载照片）+ 分段方式状态（天/月/活动，settings store 持久化）
3. **右侧导航**：基于 monthly / timelines 渲染导航，滚动高亮跟随（IntersectionObserver 或滚动位置计算）+ 点击跳转（已加载锚点滚动 / 未加载重置拉取）
4. **滚动加载**：PhotoGrid 改为滚动追加（pageSize=100，触底加载下一页追加），移除分页组件，保留筛选/搜索
5. **排序收敛**：移除排序下拉框与「文件名/导入时间」选项，保留升降序切换按钮
6. **与连拍折叠联调**：确保分割线在三级展示（全部展开/精细折叠/模糊折叠）下正确，组折叠不影响分割线
