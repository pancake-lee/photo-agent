# 主题发现（选题建议）— 设计文档

> 当前功能的设计描述。历史时间线和评估记录已归档至 `docs/archive/topic-discovery/2026-07-27-5-topic-discovery-hub.md`。

---

## 1. 功能概述

主题发现是 AI 主动为用户挖掘选题的功能。它不等用户提问，定期扫描照片库，以"编辑视角"发现用户没想到可以放在一起的照片组合，产出包含**叙事角度 + 推荐照片序列**的选题提案。

**解决的问题**：用户不知道发什么、经常断更。AI 像编辑提案一样主动推送选题，用户像主编一样审阅和打分。

**与聚类的区别**：聚类按视觉相似度分组，输出"这些照片很像"的静态分类。主题发现寻找跨上下文的连接，输出"这组照片可以这样发"的动态选题提案。

**与摄影主题分析（§2.5）的区别**：主题发现是 AI 主动推送（push），分析是用户主动提问（pull）。

## 2. 使用方式

### 2.1 自动生成选题

点击「自动生成选题建议」按钮，AI 自动完成以下过程：从图库中随机采样 3 张照片 → 基于这些照片产生 1 个编辑视角的选题直觉 → 围绕直觉从全库检索相关照片并扩展选片 → 最终输出 1 条完整的选题提案。

整个过程约 30-60 秒，用户等待后即可在列表中看到新生成的选题卡片。

### 2.2 手动选题

点击「手动选题建议」打开向导。用户可以：

- **自选照片**：在照片选择器中浏览、搜索、多选照片作为素材。也可以点"随机选取"让系统帮你挑 3 张
- **可选填直觉**：如果你已经有明确的选题方向（标题、角度、理由），可以直接填写，AI 将围绕你的方向选片；不填则完全由 AI 发挥

提交后，系统根据你提供的信息走管线：选了照片又填了直觉 → AI 直接从你选的照片中挑最佳组合；只填了直觉 → AI 围绕你的直觉从全库搜照片；只选了照片 → AI 基于这些照片发现选题。

### 2.3 查看选题详情

点击选题卡片上的「详情」按钮，打开详情弹窗。弹窗中展示 AI 生成这条选题的完整过程，每个处理步骤以可折叠卡片呈现：

- **采样步骤**：AI 随机选取了哪 3 张照片作为灵感种子
- **直觉步骤**：AI 基于这些照片产生了什么选题直觉（标题 + 角度 + 理由）
- **RAG 检索步骤**：AI 围绕直觉从全库检索了哪些相关照片，每张照片的匹配度
- **多样性过滤**：检索结果按日期分组，每组最多保留 2 张（避免同一天连拍照片挤占候选池），可以看到哪些被保留、哪些被移除
- **提案步骤**：AI 最终输出了什么——标题、叙事角度、推荐照片序列（每张照片在叙事中扮演什么角色）
- **校验步骤**：AI 做了哪些检查（照片 ID 是否有效、时间跨度是否 ≥ 7 天）

卡片默认折叠数据区，点击展开可看到照片缩略图、prompt 文本、LLM 原始响应等。

**注意**：AI 处理过程的追踪数据保留 7 天，超过 7 天的旧记录只能看到最终结果，"追踪数据已过期"。

### 2.4 编辑中间结果并重跑

如果对某个选题不满意，可以在详情弹窗中编辑任意步骤的输入数据，然后从该步骤重新运行。例如：

- 觉得 AI 的直觉不够好 → 修改直觉的标题和角度 → 重跑（AI 基于新直觉重新选片和生成提案）
- 觉得采样照片太偏 → 换一组采样照片 → 重跑（AI 从头重新走完整流程）
- 对最终提案略作调整 → 修改提案内容 → 重跑

重跑时页面显示阶段进度条（灵感发现 → 扩展选片 → 生成提案），完成后产生一个新版本。各版本可切换查看。

### 2.5 评分与删除

每条选题卡片上有 1-5 星评分。hover 时临时高亮预览，点击任意星星设定分值，hover 到当前分值可取消（恢复 0 星）。评分持久保存。不需要的选题可删除。

## 3. 选题提案的结构

每条选题提案包含以下信息：

- **标题**：20 字以内，有编辑吸引力（如"城市剪影志"）
- **叙事角度**：30-60 字，说明"这组照片为什么值得发"。不是简单归类（"一组蓝色照片"），而是编辑视角的叙事（"从晨光到深夜，城市在不同时刻呈现的三种面貌"）
- **推荐照片序列**：5 张以上，每张附叙事角色（开篇、对比、高潮、收尾等），照片按叙事逻辑排列而非时间或相似度
- **发布理由**：为什么这组选题有发布价值
- **质量约束**：照片时间跨度 ≥ 7 天（确保不是同一次拍摄的连拍组合），所有推荐的照片都经过有效性校验

## 4. 管线设计思路

选题的生成过程是一个三阶段管道。不是"按属性找照片"（那会产生同场景连拍组合），而是"先想角度再选照片"。

### 4.1 为什么是随机采样

传统做法是按统计聚合找照片——高频属性值、稀有值、季节规律。但摄影师在同一个场景会连拍多张相似照片，它们共享同一组属性，按属性匹配必然选中同一次拍摄的照片。

随机采样引入偶然性——从不同日期随机挑 3 张照片组合在一起，LLM 被迫在看似无关的照片之间寻找叙事连接。这恰好是"编辑视角"的核心——发现用户自己没意识到的跨上下文线索。

### 4.2 三个阶段的职责

**Stage 1：灵感发现**。随机 3 张照片（不含拍摄日期）交给 LLM，让它像编辑翻看素材一样，输出 1 个选题直觉。不暴露日期是为了避免 LLM 按时间线归类（如"2024 年春天"），强制它基于视觉内容建立关联。

**Stage 2：扩展选片**。用直觉标题和角度做语义检索，从全库找到与直觉相关的照片（通过 ChromaDB 向量检索），然后按日期分组过滤——同一天最多保留 2 张，确保候选池在相关的同时具备时间多样性。

**Stage 3：沉淀提案**。将直觉 + 候选照片（这次附上拍摄日期）交给 LLM，生成完整的结构化提案。此时暴露日期，让 LLM 能构建合理的时间叙事。提案经过两项后处理校验：photo_id 有效性（AI 可能输出截断或编造的 ID，会被自动检测和替换），以及时间跨度（如果序列跨度不足 7 天，自动从候选池替换首尾照片来拉大跨度）。

### 4.3 核心设计原则

1. **先想角度，再选照片**：随机采样激发灵感，RAG + LLM 围绕角度选片。避免"按属性找照片"的惯性
2. **引入偶然性**：随机采样不是放弃控制，而是打开 LLM 不会主动探索的组合路径
3. **多样性在位**：Stage 2 按日期分组约束，确保候选池不全是同一天的连拍
4. **信息分层**：Stage 1 不暴露日期（避免按时间线归类），Stage 3 暴露日期（用于构建时间叙事）

## 5. 关键设计决策

### 5.1 为什么每次只生成 1 个选题

最初设计是每次 6-9 张随机采样 → 2-4 个直觉 → 2-4 个提案。后收窄为 3 张 → 1 个直觉 → 1 个提案。

理由是数据模型统一：让"一次运行 = 一条记录 = 一个版本链"。此前 N 个提案共享同一个 trace_id（处理过程记录），导致"这些卡片是什么关系"的困惑。另外，3 张有代表性的照片足以激发 1 个有价值的角度，2-4 个的性价比不高。

### 5.2 为什么不在详情弹窗放版本时间线侧边栏

最初设计了左边栏版本时间线 + 右边步骤列表的双栏布局，后简化为单栏。两个原因：大部分选题只有 1 个版本，侧边栏空占空间；版本管理是低频操作，不需要始终可见。版本数据保留在存储中，后续需要时可以恢复。

### 5.3 为什么选了 JSON 文件存储而非 SQLite

选题记录单条体积大（含完整版本 + 步骤快照），查询模式简单（全量列表 + 单条 CRUD），JSON 文件 + 线程锁足够。与项目已有的黄金用例、聚类结果存储模式一致，不引入新基础设施。

### 5.4 已废弃的设计方向

- **按属性匹配的三维度分析**（高频未成组 / 时间线规律 / 稀缺优质）：产出均为同场景连拍组合，不符合"发现用户没看到的连接"的功能初心。已完全移除
- **每次生成 2-4 个选题**：收窄为 1 个（§5.1）
- **详情页左边栏版本对比**：改为单栏（§5.2）
