# v1.0.17 版本归档

> 归档日期：2026-09-07  
> 涵盖范围：v1.0.16（2026-09-02）之后完成或取代关闭的任务  
> 版本主题：**Agent Runtime V2 可靠性与照片交付闭环**

## 版本概述

本版本完成 Runtime V2 的 SQL 安全、观察状态、恢复控制、无进展终止、文案事实质量和多匹配澄清能力，并以故障注入与真实山西请求回归验证恢复效果；同时收口聊天日期时区语义、相对旅行日、候选交付、Trace 可定位性、NEF 元数据隔离和批量下载体验。

**关键结果**：

- 完成 AR2-1–AR2-7、CQ7、DL1、AR11–AR14、HARN1，共 14 项任务；CQ4 作为被 Runtime 承接的专用管线一并归档
- Runtime 对临时故障、无效决策、重复状态、低质量文案与多旅行匹配均有可验证的恢复或停止路径
- 故障注入基线：恢复成功率 100%、正确停止率 100%、无谓重试率 0%
- 聊天和 Runtime 按本地时区统一日期语义；候选交付同时保留完整文案，并排除 NEF 记录进入检索与交付
- 图片管理和聊天结果均支持服务端流式 ZIP 批量下载

## 任务总览

- Runtime V2：AR2-1–AR2-7，覆盖只读 SQL、六态 Observation、Guardrail 恢复预算、无进展检测、文案质量门、多匹配澄清与故障注入指标。
- 对话查询：CQ7，聊天 SQL 的日期语义统一到本地时区。
- 图片交付：DL1，服务端流式 ZIP 和图片管理、聊天结果两处入口。
- Runtime 体验：AR11–AR14，相对日澄清、候选交付、Trace 定位、文案与 NEF 隔离。
- Harness：HARN1，项目专项回归阈值和双协作文件索引修复。
- 已取代：CQ4，Compose 专用管线由 AR Runtime 挑选能力承接并退役。

## 主要变更

### Runtime V2 可靠性

- SQL 只读校验支持 `WITH ... SELECT`，同时继续用危险关键字拦截可写 CTE 旁路。
- Observation 增加六态分类；Guardrail 按状态实行有界重试、修复或再决策，且受时长、成本与恢复次数预算约束。
- 以事实、候选、完成要件和近期错误组成状态签名，连续无进展时先要求换策略，再确定性停止。
- 文案事实评委与生成器复用同一照片上下文，并允许原始用户请求中的旅行和相对日期事实；无法观察真实图片的选片阻断评委已移除，避免误杀有效选片。
- 时间线名称存在多匹配时改为澄清，复用 AR11 的会话续跑；相对旅行日及缺少年份日期不再无依据猜测。

### 交付与数据语义

- 聊天 SQL 的日期、年月、时分过滤和字段说明统一使用 SQLite `localtime` 语义。
- “尽可能多、供二次挑选”交付跳过代表性压缩，但仍完成标题和正文；超阈值时保留图文工坊入口。
- NEF 仅作为 JPG 相邻原始资产保存，动态显示角标，不再创建照片、描述或向量记录；历史 NEF 元数据和关联向量已清理，原始文件未删除。
- 新增照片 ID ZIP 下载接口：完整校验后直接流式输出，安全处理重名；图片管理多选和聊天照片结果均已接入。

### 可观测性与工程规则

- 人可读 `agent.log` 在 Runtime 请求开始、payload 落盘和结束时输出实际 Trace JSONL/payload 路径，JSON 日志契约不扩展路径字段。
- 恢复项目专属 P@10/MRR 显著下降阈值，并将 AGENTS.md 与 CLAUDE.md 的未来需求索引同步到现存文件。
- CQ4 Compose 专用管线已删除；其连拍折叠、候选收缩和深链能力迁入 Runtime，Compose 阈值配置继续复用。

## 验证结果

- Agent 全量单测最高达 300/300 通过；故障注入集 10/10 通过，覆盖七类故障的恢复或正确停止。
- `python -m unittest discover -s tests`、相关 Go Service 测试、前端下载测试与 `pnpm build` 均在对应任务交付时通过。
- AR2-7、DL1、AR11–AR14 分别完成用户实际请求或人工验收；其余条目以自动验证关单。
- HARN1 已通过 `sync.sh check photo-agent`，16 个公共块与 pancake 基准一致。

## 已知边界与后续入口

- AR15 暂缓：Runtime 目前仍以社交发布目标为中心，第二种开放目标类型的通用化升级尚未规划。
- BQ3 暂缓：自由只读 SQL 仅限受信任本地开发环境；进入共享、多人或生产环境前，必须按 [FR-11](../design/2099-01-01-future-requirements.md#fr-11-开发阶段的鉴权与自由-sql-查询收敛) 恢复鉴权并收紧查询能力。
