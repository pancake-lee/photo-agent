# v1.0.14 版本归档

> 归档日期：2026-08-28  
> 涵盖范围：v1.0.13（2026-08-27）之后完成的任务  
> 版本主题：**对话查询链路诊断修复与资产审核收尾**

## 版本概述

本版本以「山西请求」这一真实对话样本为主线，为 tool 与 sql 两条链路补齐全阶段诊断日志，修复 Tool Calling 单轮循环与属性值获取崩溃，让 SQL 生成理解时间线字段并改善无法回答体验；同时收尾资产质量闭环的两个审核缺陷（批量审查全量误报、坏图描述漏判），并确立「验证流单向、人工验收即终态」的关单规则。

**关键结果**：

- 完成 CQ1、CQ2、CQ3、CQ5、CQ6、AQL2-1、AQL2-2，共 7 项任务
- 通用聊天与 Text-to-SQL 链路具备按阶段、按轮次的诊断日志，线上卡点可从 `logs/agent.log` 直接定位
- Tool Calling 改为有界多轮循环（`llm.tool_max_rounds` 可配置），上限时强制总结兜底
- SQL 生成理解 timeline 等关键字段语义，「第一天」类问题可生成首日子查询；无法回答哨兵不再原样展示
- 批量 VLM 审查误报根因（Python SDK 生成物缺 6 个状态字段）修复，`make api-cli` 重新生成
- 坏图描述审核补充已证实措辞，vlm_prompt 新增 `image_integrity` 结构化字段；DSC_9985 完成原地修复
- 关单规则改为验证流单向：AI 自动验证前置，用户人工验收即终态，AI 不反向核验

## 主要变更

### 对话查询链路（诊断与修复）

- `[tool]` 阶段日志覆盖路由分类、工具加载、每轮模型调用、每次工具执行（含请求路径、HTTP 状态、耗时）与最终生成；首次响应不含 tool call 时以 warning 标注。
- `_tool_node` 由"单轮工具调用"重构为有界循环：每轮执行全部 tool_calls 并追加 ToolMessage，无 tool_calls 即收敛；达上限（缺省 20，可配置）后以不带工具的调用强制总结。
- 属性值接口返回的类型化模型经 `sdk_to_dict` 转换后再使用，消除 `AttributeError` 导致的纯 RAG 降级。
- `[sql]` 阶段日志覆盖 schema 字段数、属性值计数、LLM 原始输出、生成 SQL、无法回答哨兵告警、执行行数与节点异常（含堆栈）。
- schema 文本为 28 个关键字段拼接中文语义并注明 SQL 列名规则；few-shot 增加时间线查询与「第一天」首日子查询示例；哨兵 SQL 检测后跳过执行，返回可理解的说明与换问法建议。

### 资产质量闭环收尾

- 批量审查全量误报（1323 张）定位为 Python swagger SDK 生成物缺 `vlm_status` 等 6 个字段：proto 新增后未重新生成 SDK，列表字段反序列化时被丢弃。`make api-cli` 重新生成后误报归零。
- 坏图描述审核漏判（DSC_9985）修复采用 A+B 组合：关键词黑名单补充故障失真、异常显示画面、花屏等 6 个已证实措辞（存量立即生效）；vlm_prompt.md 新增 `image_integrity` 字段（normal/corrupted/test_pattern），审核解析该结构化结论（新生成描述免疫措辞变化）。
- 「无具象+条纹」组合规则因会把纯抽象摄影永久卡在待复核而否决；方案 C（源头图像统计预检）工程量大、误报难控，不纳入。

### 工作流规则

- 关单规则确立「验证流单向」：交付人工验收前 AI 先穷尽自动验证（回归测试、脚本、Trace/日志自查），`（用户）` 操作仅限 AI 无法自动执行的最后一环；用户确认验收成功即终态，AI 同一轮直接改 `Done`，不反向核验用户结论。
- backlog 交接模板以「AI 自动验证 + 关单方式」取代「AI 关单证据」；CLAUDE.md、AGENTS.md、work-modes.md、harness.md 四处同步。

## 验证结果

- Agent 全量测试 100/100 通过（CQ6、AQL2-1 轮）；Go service 包全量测试与 `go build ./...` 通过（AQL2-2 轮）。
- 活体验证：山西时间线查询返回正确结果，「第一天」生成首日子查询；Text-to-SQL 全链路日志完整。
- 用户运行时验收：CQ2（多步工具请求）、AQL2-1（误报归零）、AQL2-2（DSC_9985 被标待复核并原地修复，新描述含 `image_integrity: "normal"`）均于 2026-08-28 确认通过。
