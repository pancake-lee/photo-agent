# v1.0.19 版本归档

> 归档日期：2026-09-07  
> 涵盖范围：v1.0.18（2026-09-07）之后完成或取代关闭的任务  
> 版本主题：**Agent Runtime V4 多轮上下文与跟进续跑**

## 版本概述

本版本让会话历史首次进入推理链路：系统以有界上下文保留近期原文、压缩早期轮次并保留照片引用，识别跟进请求后将其消解为可执行的完整问题；Runtime 保存任务快照，按受影响部分局部续跑而不重复有效工作。真实四轮回归进一步验证改文案、补选及非跟进请求的行为；补选路径中暴露的模型行为依赖已由完成要件的确定性规则修复。

**关键结果**：

- 完成 AR4-1–AR4-10 共 10 项任务；AR16、AR17 由 AR4 系列展开实现后关闭。
- V4 两轮评估均为 8.3/10，最终复评与执行合理性评估为 8.0/10，通过既定 8.0 循环目标。
- 授权真实 LLM 四轮回归 PASS：首轮发帖交付、仅改文案、补选新增且保留旧片、非跟进 SQL 查询。
- 长会话截断后的轮次标签维持原始会话序号；AR4 变更范围的 Ruff F541 违规已清除。

## 任务总览

- 会话上下文：AR4-1 选择/压缩历史并保留有界照片 ID 引用；AR4-9 修复截断历史轮次重编号。
- 跟进与续跑：AR4-2 识别、消解并让全部下游消费完整问题；AR4-3 保存 Runtime 快照并按局部失效续跑。
- 评估与验证：AR4-4 建立多轮金用例与 V4 基线；AR4-5 完成独立真实 LLM 回归；AR4-10 清除代码卫生违规。
- 补选保障：AR4-6 让早期历史照片 ID 可引用；AR4-7 在归约层确定性保留旧片；AR4-8 强制补选时重新执行选片。
- 已取代：AR16、AR17 的原始问题已分别展开并由 AR4-1–AR4-4 交付，不再作为独立任务保留。

## 主要变更

### 有界会话上下文与跟进消解

- Context Builder 对会话历史实施近期原文窗口与早期摘要，照片只保留 ID 引用；当前消息优先于既有约束。
- 入口在有历史时识别 `followup`，经独立消解生成完整问题与受影响部分；SQL、RAG、Tool、Combined、Runtime 五条路径统一消费该结果。
- 截断后历史块使用原始轮次编号，避免“第二组”“第六轮”等序数指代错绑。

### Runtime 局部续跑与补选确定性

- Runtime 任务状态可序列化保存为会话快照；跟进只使范围、选片或文案等受影响里程碑失效，有效产物继续复用。
- 补选语义与重选区分，归约层以保留在前、去重追加的规则维护旧入选。
- 若补选后选片仍待办，完成检查不允许保留集直接满足选片要件，确保选片能力实际重跑并产生新增候选。

### 评估资产与工程治理

- 多轮金用例覆盖改文案、补选重写、换范围重跑和快照 JSON 往返；V4 基线登记 Context Sufficiency、Context Utilization、Constraint Retention、Multi-turn Task Success。
- 真实回归脚本与日常测试物理隔离，先检查后端健康；仅在用户明确授权时读取真实照片并调用 LLM。
- 清除状态摘要的无插值 f-string，针对性 Ruff 通过。

## 验证结果

- Agent 全量离线回归最终为 **408 passed、6 subtests passed**；新增 10 轮截断序数回归通过。
- `ruff check internal/context/builder.py internal/runtime/state.py tests/test_context_builder.py` 通过。
- 授权真实回归四轮 PASS：`2961a71afec3`、`41de4080a340`、`449c410f0a8f`、`1b98dd14a6cf`。第三轮入选从 1 张增至 2 张且旧片保留；第四轮正确路由 SQL 并返回 136。

## 已知边界与后续入口

- AR18（待规划）：新开放目标仍受封闭入口分类及 `rag` 兜底限制；按既有决策在 V4/V5 后独立评估。
- BQ3（暂缓）：自由只读 SQL 仅限受信任本地开发环境；进入共享、多人或生产环境前，必须按 [FR-11](../design/2099-01-01-future-requirements.md#fr-11-开发阶段的鉴权与自由-sql-查询收敛) 恢复鉴权并收紧查询能力。
- `selection_add` 当前只映射发帖目标；对比或主题目标出现多轮补选需求时再评估扩展。
