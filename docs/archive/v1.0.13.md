# v1.0.13 版本归档

> 归档日期：2026-08-27  
> 涵盖范围：v1.0.12（2026-08-26）之后完成的任务  
> 版本主题：**AI 照片资产质量闭环与对话体验收敛**

## 版本概述

本版本建立从 VLM 输入到 Embedding、检索、黄金评估及对话 Trace 的照片资产质量闭环，确保异常描述和过期向量不会污染检索结果；同时收敛对话布局、检索粒度呈现与公共照片列表交互，并恢复 Agent 全量测试门禁。

**关键结果**：

- 完成 AQL1-1 至 AQL1-8、CH2、HW1、QA2、DOC1，共 12 项任务
- VLM 请求图与原始 JPG 身份隔离并可预检；描述质量、向量版本和检索准入以实时结论贯通全链路
- fine/coarse 连拍集合保留未分组照片，真实对话在三种粒度下均可召回 `DSC_1813.jpg`
- 对话界面消除双重滚动，持久化并展示每条回复实际使用的检索粒度；公共 `PhotoThumbList` 统一相关照片展示和原图下载
- Agent 全量测试恢复至 86/86 通过；AQL 专题设计、中枢和 backlog 的验收状态已同步

## 主要变更

### AI 照片资产质量闭环

- VLM 仅接收可解码的 JPG/JPEG 请求图；请求级临时文件按照片和来源隔离，避免同名文件或跨目录材料错配。
- 描述经本地质量规则判定后才可进入 Embedding；描述重生成、质量拒绝和输入失效会使旧向量失效。
- 描述质量和 Chroma 描述版本改为实时推导，不再依赖 SQLite 中易滞后的健康字段。照片列表、详情、批量审查、队列、检索和评估共享同一结论。
- 批量 VLM/Embedding 操作先做本地审查、展示缩略图预览和数量，再由用户确认处理；单张异常可在既有详情中原地重跑。
- 黄金评估持久化期望资产健康和版本快照；对话 Trace 同步记录命中照片的资产证据。
- fine/coarse 集合改为“连拍组封面 + 当前档位未分组单张”，使未分组照片不再从连拍粒度检索中丢失。

### 对话与公共图片列表

- 对话右侧改为标题、消息区、输入区三段式布局，仅消息区滚动。
- assistant 消息及会话保存实际检索粒度和最近选择；新旧历史分别显示准确标签或“粒度未记录”。
- Markdown 图片保持完整比例且尺寸与图片管理卡片接近；相关照片统一复用 `PhotoThumbList`。
- `PhotoThumbList` 为所有调用位置的实际图片提供原图下载，且不会误触预览、选择或删除。

### 工作流与质量保障

- 明确 `WIP` 仅用于 AI 开发或自动验证，新增 `待用户验收` 作为唯一人工交接状态，并规定用户操作、最小回传和 AI 关单证据。
- Text-to-SQL 测试夹具与 SDK 响应模型对齐，few-shot 断言同步至当前 12 条示例；Agent 全量测试恢复绿色。
- AQL 专题设计、轻量修复、实时状态设计和中枢文档均已回写完成状态与验收证据。

## 验证结果

- Go 全量测试、Python 定向测试、静态编译和前端生产构建均通过。
- `agent/.venv/bin/python -m unittest discover -s agent/tests`：86/86 通过。
- Python 资产质量与连拍检索定向测试通过；真实 HTTP L2、黄金用例和用户浏览器验收均确认 `DSC_1813.jpg` 在 fine/coarse 对话中可召回。
- 用户已确认 AQL 批量操作、对话界面和连拍粒度交互验收通过；相关黄金快照与 Trace 已保存在版本关联证据中。
