### W13 重启后主窗口只剩标题栏

- **状态**：Done
- **背景**：Windows 任务栏预览只剩标题栏，桌面上看不到主窗口。故障机器的 `window.json` 记录了 `134 × 37` 的尺寸和 `(-32000, -32000)` 的坐标。最小化后退出时，客户端把最小化矩形当作正常窗口保存，重启时又恢复了这组数据。
- **方案**：最小化退出时保留已保存的窗口状态，启动时对过小的历史窗口尺寸按既有规则重新居中初始化。
- **实施**：最小化退出时跳过写入。启动时，保存宽度低于 320 或高度低于 200 逻辑像素则按主屏 70% 居中，并保存新状态。
- **AI 自动验证**：用实测的 `134 × 37` 和 `(-32000, -32000)` 验证重置，正常尺寸、负坐标和最大化标记的恢复用例通过。客户端全量 Go 测试通过，Windows x64 可执行文件已重新构建。
- **用户验收**：2026-11-13 验收通过。

### AR18 入口分类封闭集，新开放目标静默降级

- **状态**：Done
- **背景**：入口为一次性 LLM 分类器，输出七类封闭标签（sql / rag / tool / combined / runtime_post / runtime_comparison / runtime_topics），未命中时静默兜底到 `rag`；Runtime 目标空间固定三种（social_post / photo_comparison / topic_discovery）。不属于既有类别的新开放请求（如废片整理、年度报告）会被降级为单步检索或误配目标契约，用户得不到"系统不认识该目标"的信号。注意：这是 V3 设计文档明示的兼容性边界（刻意取舍），但开放目标侧确实没有出口。修正一点：匹配是 LLM 分类而非字面关键词，泛化能力强于规则匹配，问题在结构不在形式。
- **严重程度**：P2，单步请求走封闭类别+兜底是合理设计（V5 也保留）；缺口仅在开放目标侧扩展性与可感知性。
- **归属**：V4/V5 完成后独立评估（2026-09-07 决策）。V4 多轮落地时会被迫触及入口的最小跟进识别切片（跟进消息不走七类分类），该切片归 V4，不改变 AR18 整体延后。
- **证据**：[V0–V3 目标达成回顾](eval/reports/2026-09-07-v0-v3-goal-retrospective.md)。
- **分析**：V3 已将 Runtime 循环与目标契约分离，但 `state.new_goal()`、目标能力白名单和入口分类提示词仍各自枚举三种目标；新增目标依然需要实现其契约与能力组合。AR18 的目标不是让任意自然语言任务直接进入 Runtime，而是把入口区分为「既有直接请求」「已注册开放目标」「尚未注册的开放目标」；后一类必须向用户显式说明当前不支持，不能被路由为 RAG。入口描述应由目标注册表提供，避免每增一个目标再修改分类器的静态词表。
- **决策**：2026-09-07 用户选择方案 A（受控开放目标准入）。开放表示目标可被注册、验证和观测，不表示 Runtime 无契约地执行任意新业务。
- **方案**：
  - 建立目标注册表作为 Runtime 目标的唯一入口描述源：每个已支持目标同时声明目标标识、面向分类器的用户意图描述和既有任务契约。入口不再维护与 Runtime 契约平行的目标枚举；新增目标须先在此注册，再由其契约限定可用能力、完成要件、观察和交付。
  - 入口分类改为可校验的结构化路由决策：普通单步请求仍可选择 SQL / RAG / Tool / Combined；开放请求只可命中已注册目标，或明确成为 `unsupported_goal`。分类器输出不合法、目标名未注册、以及无法可信归入直接路径的情形，都进入显式说明，不再静默转为 RAG。
  - 为未支持目标增加专门交付：说明系统识别到的是尚未支持的照片库任务，简述当前边界并列出可用开放目标；若请求涉及删除、标记或整理等写操作，明确该能力尚未实现，绝不执行或暗示已执行。该结果作为独立技术终态写入请求级 Trace 和助手消息关联记录。
  - 跟进消解同步采用同一目标注册表：只有已注册目标可恢复或续跑 Runtime；对未知开放目标或不合法消解输出，保留改写后的请求并转入显式未支持交付，不能借由 `rag` 兜底绕过准入。
  - 不建立通用探索 Runtime、不放宽现有目标契约，也不改变 SQL/RAG/Tool/Combined 在其适用范围内的正常降级策略。
- **任务列表**：
  - AR18-1：收敛目标契约与入口描述。涉及 Runtime 目标定义、入口路由与跟进消解；将三种现有目标迁入统一注册表，保持已有目标的路由和契约行为不变。
  - AR18-2：实现未支持开放目标的显式交付与证据链。涉及聊天路由图、助手消息汇总和 Trace；形成稳定、无副作用的未支持终态，并保留原始/改写后的请求和识别依据。
  - AR18-3：补齐离线回归。覆盖三种已支持目标、未知只读目标（年度报告）、未知写操作目标（废片整理）、非法分类输出与多轮跟进；断言它们均不会进入 RAG 或 Runtime 的错误目标契约，同时保留现有直接请求回归。
- **验收**：
  - [x] 入口的已支持目标清单由目标注册表提供；新增目标不再需要同步编辑静态分类标签表。
  - [x] 「整理废片」「生成年度报告」等未注册开放请求得到明确未支持说明，不调用 RAG，且不进入现有 Runtime 目标。

## 产品定位决策

**从**：“个人摄影资产 AI 助手”（泛化，容易堆砌技术）
**到**：「AI 选题助手」，AI 像员工提案，用户像主编审阅。

核心 workflow：拍摄→入库→AI 定期推送选题建议（推荐照片组合 + 发角度）→用户判断选哪个、如何微调→用户自己发布。

**主动不做的事**：

- 不自动发布到社交平台（发送由用户操作）
- 不替代审美判断（AI 推荐，用户决策）
- 不做多模态检索/以图搜图（选题场景不需要）
