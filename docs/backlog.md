## Harness 工作流

### HW1 任务闭环与用户验收交接

- **状态**：Done
- **背景**：开发和自动验证已完成、但尚需浏览器或部署环境验证的任务，曾继续标为 `WIP`，既没有明确告诉用户下一步，也没有规定用户确认后由谁检索 Trace、回写状态并关闭任务。结果是 AQL1-8 已具备验收条件却未被主动推进到 Done。
- **分析**：现有生成模式仅要求将运行时项“留待用户部署后确认”，缺少独立状态、验收负责人、对用户的操作指引和确认后的关单动作；`WIP` 因而同时表示“开发未完成”与“仅等待用户”，无法从 backlog 本身判断下一步。
- **方案**：在 Harness 中建立 `待用户验收` 状态，作为代码和 AI 自动验证全部完成后唯一允许的人工交接状态。每一项人工验收必须在 backlog 中写明 `（用户）` 操作、可观察预期、所需最小回传和可由 AI 自动读取的证据来源；生成器完成后主动、醒目地提出该操作。用户确认后，AI 先自行查验 Trace、日志或持久化结果，再立即回写 Done；只有缺少可自动验证的证据时，才向用户索取最小必要信息。无需用户操作的任务不得以 WIP 或待用户验收滞留，AI 完成自动验证后直接关闭。`WIP` 仅用于 AI 仍在执行开发或自动验证的阶段，并记录 AI 的下一步和阻塞原因。
- **任务列表**：
  - ✅ 更新状态定义、状态流转和 backlog 条目模板，明确 WIP、待用户验收、Done 的边界和必填交接信息。
  - ✅ 更新生成模式的收尾检查：区分自动验收与用户验收；对后者强制生成可执行的用户指引与明确提问。
  - ✅ 更新用户确认后的关单流程：AI 自动查验已有证据、更新总览和详情状态；无自动证据时再请求最小回传。
  - ✅ 同步更新 Harness 概览、`AGENTS.md` 与 `CLAUDE.md`，并清理现有条目中状态与验收叙述不一致的问题。
- **已验证**：`AGENTS.md` 与 `CLAUDE.md` 除文件身份标题和互指名称外内容一致；`docs/handbook/work-modes.md`、`docs/harness.md` 和 backlog 已包含同一状态语义与用户验收交接规则；AQL1-6、AQL1-7、CH2 已由错误的 Done 状态改为 `待用户验收`，并补齐用户操作和 AI 关单证据。
- **验收**：任一需要浏览器/部署验证的已开发任务都会以 `待用户验收` 显示，backlog 可独立说明用户做什么、预期什么和 AI 将如何关单；生成任务的最终回复会主动提出该验收。用户确认后，存在 Trace/日志时 AI 无需用户导出文件即可核验并改 Done；纯自动任务不会停在 WIP。`AGENTS.md` 与 `CLAUDE.md` 保持一致。
- **评估**：8.4/10（正确性 8.5、健壮性 8.4、可维护性 8.6、简洁性 8.3），详见 [2026-08-27-current-backlog-done-reassessment.md](../data/eval_reports/2026-08-27-current-backlog-done-reassessment.md)。

## AI照片资产质量闭环

- **状态**：AQL1-1 至 AQL1-8 已完成
- **分组**：AI照片资产质量闭环
- **背景**：`DSC_1813.jpg` 的原图是佛像与人物合照，VLM 却读取了错误的故障彩条请求缩略图；当前至少 121/1,436 张照片有同类异常描述。现有管道只以调用/写库成功计数，错误描述仍会嵌入并污染黄金用例和对话；失败和异常也无法跨任务查询。详情入口的 AI 修复能力不一致。
- **分析**：根因是 VLM 请求缩略图的身份没有包含源 JPG 的完整路径与版本，且已有材料被无条件复用，造成同名 JPG/NEF 或跨目录文件错配。更深层缺陷是没有区分技术成功与资产质量成功，也没有可持久化的健康状态、处理履历和检索准入规则。
- **方案**：建立“JPG 原图/预览图—VLM 请求缩略图—VLM 描述—Embedding”的轻量质量闭环：调用前只做本地输入预检，调用后只做本地描述校验；异常状态复用缩略图现有 VLM/Embedding 图标和照片详情区域展示。修复不引入独立问题工作区或修复任务：单张在详情直接重跑 VLM 并自动更新 Embedding；批量操作复用顶部 VLM/Embedding 按钮，在确认弹窗中汇总待处理和疑似异常照片。只有健康且版本一致的资产可参与检索、对话和黄金用例评估。完整需求见 [AI 照片资产质量闭环设计](design/2026-08-26-4-ai-asset-quality-loop-design.md) 与 [轻量修复交互设计](design/2026-08-27-1-ai-repair-interaction-design.md)。
- **子任务与串行依赖**：AQL1-1 → AQL1-2 → AQL1-3；AQL1-2 与 AQL1-3 完成后进入 AQL1-4；AQL1-3 与 AQL1-4 完成后进入 AQL1-5；AQL1-5 → AQL1-6 → AQL1-7。AQL1-5 先让单张异常在既有详情中可见、可原地修复；AQL1-6 再让顶部批量 VLM/Embedding 操作完成全库审查、汇总确认与自动处理。
- **生成阶段与可见验收**：
  - 阶段 1–6（AQL1-1 至 AQL1-6）：已完成输入预检、实时描述质量与向量准入、既有界面原地修复、批量审查和确认处理。
  - 阶段 7（AQL1-7）：运行黄金用例和对话回归。验收是保存修复前后证据，并区分数据健康、检索和回答质量。

### AQL1-1 VLM 请求缩略图身份与预检

- **状态**：Done
- **目标**：VLM 请求缩略图只能来自同一张、同一版本的 JPG 源照片，停止新增错配并在调用前拦截。
- **涉及模块**：Go 存储/VLM 压缩服务、上传后照片元数据、预览图与请求缩略图生命周期、单元测试。
- **方案**：区分应用预览图和 VLM 请求缩略图：前者是已有网页展示产物，后者在调用前从 JPG 原图或预览图实时生成，可采用请求级临时文件。请求缩略图按照片逻辑 ID、JPG 源版本和转换规格隔离；复用前执行零 Token 输入预检，校验可读性、格式/尺寸、来源与内容指纹，并将 JPG 原图规范化预览和待发送缩略图做本地视觉一致性比对。不匹配、不可读或无关联材料时在本地重建并记录异常，不调用 VLM；NEF 保持不参与 VLM/Embedding。
- **验收**：`DSC_1813.jpg` 的 VLM 请求缩略图可追溯到正确 JPG 原图；同名 JPG/NEF、跨目录同名、源图更新、材料损坏、视觉错配和正常复用均有测试。NEF 不得进入 VLM/Embedding，任一预检失败不得产生 VLM API 请求。
- **本阶段已实现**：VLM 输入仅接受可解码 JPG/JPEG；超限压缩产物改为每次请求独立临时文件，不再按基础文件名复用；已覆盖正常 JPG、NEF、损坏 JPG、同名跨目录临时文件隔离测试。
- **阶段验收命令**：`cd backend && GOTOOLCHAIN=local go test ./internal/defaultService/service`
- **评估**：8.6/10（正确性 8.8、健壮性 8.7、可维护性 8.4、简洁性 8.5），详见 [2026-08-27-current-backlog-done-reassessment.md](../data/eval_reports/2026-08-27-current-backlog-done-reassessment.md)。

- **目标**：持久化当前 AI 健康状态和每次处理结果，刷新或重启后仍可查询。
- **涉及模块**：SQLite 迁移与生成模型、Go DAO/服务、VLM 队列、Python EmbedQueue、状态查询。
- **方案**：每张照片维护预览图、VLM 请求缩略图、VLM、Embedding、总体健康、排除标记和版本关联；另记录批量/单张任务与阶段履历。统一待处理、处理中、健康、失败、待复核、过期、已排除的转移规则，运行时计数从任务结果派生。旧照片迁移后统一进入待审计，不误标健康。
- **验收**：单张 VLM 失败、批量 Embedding 失败和质量拒绝在照片详情、问题查询、任务摘要中结论一致，服务重启后仍可读取；无数据库外键。
- **本阶段已实现**：新增照片 AI 健康、VLM、Embedding 状态及原因字段；新增无外键 `ai_processing_history` 履历表；VLM 与 Embedding 处理结果写入状态和履历，并通过照片详情返回。

### AQL1-3 VLM 质量闸门与失效传播

- **状态**：Done
- **目标**：区分“调用返回文本”与“得到可信描述”，并立即使不可信上游的向量失效。
- **涉及模块**：Go VLM 服务、描述解析、状态服务、照片详情数据组装、VLM 测试。
- **方案**：仅接收已通过零 Token 输入预检的请求缩略图，再校验 VLM 输出非空和结构可解析；仅将明确故障画面/测试图，以及“条纹组 + 色块”等组合设为首批待复核规则，普通颜色、条纹和色块描述不单独判异常；描述重生成、质量拒绝或请求缩略图失效时统一使旧向量过期。支持重新校验和从描述开始完整修复。
- **验收**：命中故障彩条规则的调用计为待复核而非成功，可见原因且不可检索；重新生成有效描述后才可进入向量阶段。
- **本阶段已实现**：VLM 返回空文本、缺失结构化 JSON、明确故障画面/测试图及高风险组合进入待复核；普通颜色和条纹描述不再因关键词单独命中；质量拒绝会使 Embedding 状态失效，历史记录保留原因。
- **评估**：8.5/10（正确性 8.7、健壮性 8.5、可维护性 8.4、简洁性 8.3），详见 [2026-08-27-current-backlog-done-reassessment.md](../data/eval_reports/2026-08-27-current-backlog-done-reassessment.md)。

### AQL1-4 Embedding 一致性与检索准入

- **状态**：Done
- **目标**：只有健康且描述版本一致的照片与组图封面进入三个向量集合和对话上下文。
- **涉及模块**：Python EmbedQueue、Chroma、RAG、组图集合同步、黄金用例评估、Python 测试。
- **方案**：Embedding 只领取健康描述并记录来源版本；待复核、失败、过期、已排除或版本不一致时清理全量和组图旧向量。查询、集合维护、黄金用例评估与对话 Trace 共用准入语义，评估先报告期望照片健康摘要。
- **验收**：已嵌入照片变为待复核/过期后，photo/fine/coarse 与对话都不再命中；恢复健康并重嵌入后才重新出现。
- **本阶段已实现**：Embedding 队列仅领取通过 VLM 闸门的照片；成功后回写健康状态；照片检索在结果组装前统一读取健康状态，过滤异常照片和组封面，覆盖 RAG 与对话上下文。
- **评估**：8.8/10（正确性 9.0、健壮性 8.8、可维护性 8.7、简洁性 8.6），详见 [2026-08-27-current-backlog-done-reassessment.md](../data/eval_reports/2026-08-27-current-backlog-done-reassessment.md)。

### AQL1-6 批量 VLM/Embedding 审查与确认

- **状态**：Done。已以现有顶部批量操作替代旧问题工作区和持久化修复任务；用户 Web 验收与自动验证均通过。
- **目标**：用户点击已有批量 VLM 或 Embedding 按钮时，系统完成当前照片库的本地审查、汇总展示和确认后的自动修复。
- **涉及模块**：Go 全库本地描述校验与 VLM 候选查询、Python Embedding 候选查询、Web 顶部批量操作确认弹窗与缩略图预览、队列结果反馈与测试。
- **方案**：批量 VLM 点击后先本地汇总“没有 AI 描述”和“描述疑似异常”的数量，展示每类最多一行缩略图及“还有 N 张”；用户确认后只对这两类照片重跑 VLM，成功描述自动进入 Embedding。批量 Embedding 点击后汇总“描述可信但没有/已过期向量”的数量和一行缩略图，确认后只重建这些向量。两类操作继续使用现有队列进度和停止能力；队列结束显示成功/失败/仍待复核数量，不创建新页面或长期任务。审查只运行本地算法，不消耗 VLM Token，也不改写原图。
- **任务列表**：
  - ✅ AQL1-6a：批量 VLM 前执行本地审查，只将未描述和疑似异常照片纳入队列。

## 产品定位决策

**从**：“个人摄影资产 AI 助手”（泛化，容易堆砌技术）
**到**：「AI 选题助手」，AI 像员工提案，用户像主编审阅。

核心 workflow：拍摄→入库→AI 定期推送选题建议（推荐照片组合 + 发角度）→用户判断选哪个、如何微调→用户自己发布。

**主动不做的事**：

- 不自动发布到社交平台（发送由用户操作）
- 不替代审美判断（AI 推荐，用户决策）
- 不做多模态检索/以图搜图（选题场景不需要）
