### AR3-1 目标契约与通用任务状态拆分

- **状态**：Done
- **背景**：专项评估确认 Runtime 的循环和能力注册表可复用，但唯一发帖 goal 把状态、归约、完成检查和最终输出锁成一条预装管线；AR15 因此拆分为本 V3 系列的可执行条目。
- **方案**：建立由目标定义拥有的任务契约：目标声明完成要件、里程碑、可接受观察、终态解释与交付呈现；Runtime 核心只保存约束、已确认事实、产物引用、进度与错误。将照片范围、候选/精选和发布草稿迁为社交发帖目标的领域状态与归约器，保持原有权威范围和确定性检查不变量。删除从用户描述关键词推断交付模式的做法，目标与交付变体仅能由入口识别结果或显式结构化参数确定。
- **涉及模块**：`agent/internal/runtime/state.py`、`completion.py`、`graph.py`、现有 Runtime 状态/图级测试。
- **依赖**：无；完成后 AR3-2、AR3-3 才可开始。
- **验收**：社交发帖原始山西用例的状态摘要、完成语义、终态和用户输出不退化；新增目标定义无需修改 Runtime 循环或全局归约/完成检查表；关键词变化不再改变同一目标的交付语义。
- **实施与验证**：目标契约声明允许能力与观察；候选交付仅由 `delivery_mode` 结构化参数决定。Runtime/发帖回归与 V3 契约离线测试通过。

### AR3-2 Capability 分层与既有能力契约迁移

- **状态**：Done
- **背景**：当前 7 项注册能力均服务发帖链路，检索的不同实现与选片/创作方法处于同一层级，无法向 Runtime 表达 Tool、Skill、Workflow 的边界。
- **方案**：在能力契约中声明层级、适用条件、不适用条件、输入输出、错误语义和副作用；保留现有统一 Observation 与 Guardrail 接口。将直接数据访问归为 Tool，把范围解析、候选收缩、代表性选片和文案创作归为 Skill；不以目录改名或大规模重写替代契约迁移。决策上下文按当前目标和缺口只展示可用能力，暂不引入能力检索。
- **涉及模块**：`agent/internal/runtime/registry.py`、`capabilities/`、`graph.py`、能力/决策提示回归测试。
- **依赖**：AR3-1。
- **验收**：每项已注册能力都有可机器读取的层级与完整契约；无效选择仍由现有参数校验和 Guardrail 处理；山西发帖轨迹仍只使用其适用能力，且能力清单不要求 Runtime 知道具体业务实现。
- **实施与验证**：注册表增加 Tool/Skill/Workflow 层级、适用与不适用条件、输入输出、错误和副作用契约；决策仅收到当前目标允许的能力。离线契约测试通过。

### AR3-3 照片跨期对比开放目标接入

- **状态**：Done
- **背景**：专项评估的判别用例「对比 2025 和 2026 春天的洱海照片，总结拍摄进步」当前会落入单发检索，不能证明 V3 的组合复用。
- **方案**：以只读的“照片跨期对比”作为第二个 Runtime 目标：复用范围解析、检索和照片详情能力，补齐基于两组照片证据形成对比结论的 Skill。目标交付为可追溯的对比报告与引用照片，不选片、不生成发布文案、不写入草稿。入口路由先判断请求是否需要跨组证据收集和综合结论，再选择目标契约；普通检索继续留在既有直达路径。
- **涉及模块**：入口分类与 Runtime 调用边界、`agent/internal/runtime/capabilities/`、对比目标领域状态/输出、聊天过程展示与图级测试。
- **依赖**：AR3-1、AR3-2。
- **验收**：上述判别用例可进入 Runtime，完成两组范围/候选收集并输出带照片依据的对比结论；其轨迹复用既有检索/详情能力；社交发帖和普通 RAG/Combined 路由不回归；全程不修改真实照片、标签或草稿。
- **实施与验证**：新增只读 `photo_comparison` 目标与 `compare_photo_periods` Skill，报告保存两期照片 ID 依据；入口对 Runtime 对比意图选择该目标。离线替身回归验证两期证据、完成检查与输出引用。

### AR3-4 主题发现 Workflow 能力化

- **状态**：Done
- **背景**：主题发现已有稳定三阶段管线，却仍以顶层 Query 路径存在，不能作为开放任务中的可调用能力，也无法与 V3 的 Workflow 定义对应。
- **方案**：为现有主题发现建立明确的 Workflow 输入、输出、失败语义与证据边界，使它可接收照片范围并返回主题候选及其证据；保留内部候选生成、分析、评分和结果生成，不重写算法，不让 Runtime 介入其固定内部控制流。仅在目标明确需要主题发现时暴露该 Workflow，原有主题发现入口和历史记录行为保持兼容。
- **涉及模块**：主题发现服务、Runtime 能力注册与适配层、相关 API/Workflow 回归测试。
- **依赖**：AR3-2；可与 AR3-3 并行实施。
- **验收**：Workflow 可由明确范围独立调用并返回与既有管线等价的主题候选和证据；原有自动/手动选题与历史查看不退化；Runtime 得到的是单个结构化 Observation，而不是内嵌主题发现的端到端聊天路径。
- **实施与验证**：主题发现以 `discover_topics` Workflow 注册，显式范围下推至既有三阶段管线，输出单个主题候选 Observation；不写入历史。离线范围传递回归通过。

### AR3-5 V3 组合轨迹评估与回归基线

- **状态**：Done
- **背景**：V3 的成功不应只靠“新增了能力”判断，必须证明第二种开放目标复用能力、既有链路未退化，且没有用新的端到端 Pipeline 掩盖问题。
- **方案**：建立覆盖社交发帖、跨期对比、主题发现 Workflow 的离线组合用例与 Trace 断言；记录能力层级选择、目标契约、复用关系、契约失败与质量/成本/时延。真实数据或真实 LLM 回归沿用独立目录和当轮授权规则，日常自动回归只使用可控替身。
- **涉及模块**：`agent/tests/`、Trace/评估脚本、`docs/eval/baseline.md`、Runtime 专题中枢。
- **依赖**：AR3-3、AR3-4。
- **验收**：自动回归覆盖两个不同目标的完整轨迹、目标/能力不适用时的正确拒绝，以及发帖链路兼容性；基线能报告 Capability Selection Accuracy、Capability Reuse Rate、New-Pipeline Rate、Contract Failure Rate、Task Success/Cost；真实 LLM 用例未在未获当轮授权时执行。
- **实施与验证**：新增 `test_runtime_v3_contracts.py` 覆盖显式交付变体、目标拒绝、能力完整契约、跨期对比和范围化 Workflow；指标写入 `docs/eval/baseline.md`。Agent 离线全量 305/305 通过，未读取真实数据或调用真实 LLM。

### BQ3 未鉴权服务暴露任意 SQL 查询

- **状态**：暂缓
- **背景**：默认服务全局调用 `SetIgnoreAuth`，同时注册了接收调用方 SQL 文本的 QueryService。当前服务监听全部网络接口；虽使用只读数据库连接，调用方仍可读取任意可访问表和元数据。
- **严重程度**：P0，未授权数据访问风险。
- **证据**：[后端代码质量基线评估](eval/reports/2026-08-29-backend-code-quality-baseline.md)。
- **方案**：当前开发阶段保留 `SetIgnoreAuth` 与自由只读 SQL 查询，不改变接口、监听方式或开发调试效率。将风险、启动条件和后续收敛方向迁入 FR-11；当服务需要被非受信任网络、多人或真实用户访问时，必须先恢复鉴权并收紧查询能力，再继续发布。
- **验收**：FR-11 可独立追溯本决策及后续启动条件；BQ3 不进入当前开发队列。

## 产品定位决策

**从**：“个人摄影资产 AI 助手”（泛化，容易堆砌技术）
**到**：「AI 选题助手」，AI 像员工提案，用户像主编审阅。

核心 workflow：拍摄→入库→AI 定期推送选题建议（推荐照片组合 + 发角度）→用户判断选哪个、如何微调→用户自己发布。

**主动不做的事**：

- 不自动发布到社交平台（发送由用户操作）
- 不替代审美判断（AI 推荐，用户决策）
- 不做多模态检索/以图搜图（选题场景不需要）
