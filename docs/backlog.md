## AI照片资产质量闭环

- **状态**：已规划
- **分组**：AI照片资产质量闭环
- **背景**：`DSC_1813.jpg` 的原图是佛像与人物合照，VLM 却读取了错误的故障彩条请求缩略图；当前至少 121/1,436 张照片有同类异常描述。现有管道只以调用/写库成功计数，错误描述仍会嵌入并污染黄金用例和对话；失败和异常也无法跨任务查询。详情入口的 AI 修复能力不一致。
- **分析**：根因是 VLM 请求缩略图的身份没有包含源 JPG 的完整路径与版本，且已有材料被无条件复用，造成同名 JPG/NEF 或跨目录文件错配。更深层缺陷是没有区分技术成功与资产质量成功，也没有可持久化的健康状态、处理履历和检索准入规则。
- **方案**：建立“JPG 原图/预览图—VLM 请求缩略图—VLM 描述—Embedding”的可追溯质量闭环：以持久化的当前状态和处理履历呈现失败、待复核、过期与健康；请求缩略图按照片身份和源版本隔离并在发送前零 Token 预检；用确定性完整性校验和可解释的语义异常规则阻断污染；问题清单和统一详情入口支持诊断、批量发现与人工修复；只有健康且版本一致的资产可参与检索、对话和黄金用例评估。完整需求见 [AI 照片资产质量闭环设计](design/2026-08-26-4-ai-asset-quality-loop-design.md)。
- **子任务与串行依赖**：AQL1-1 → AQL1-2 → AQL1-3；AQL1-2 与 AQL1-3 完成后进入 AQL1-4；AQL1-3 与 AQL1-4 完成后进入 AQL1-5；AQL1-5 → AQL1-6 → AQL1-7。历史批量修复只在 AQL1-6 审计预览完成并经用户确认目标范围后执行。

### AQL1-1 VLM 请求缩略图身份与预检

- **目标**：VLM 请求缩略图只能来自同一张、同一版本的 JPG 源照片，停止新增错配并在调用前拦截。
- **涉及模块**：Go 存储/VLM 压缩服务、上传后照片元数据、预览图与请求缩略图生命周期、单元测试。
- **方案**：区分应用预览图和 VLM 请求缩略图：前者是已有网页展示产物，后者在调用前从 JPG 原图或预览图实时生成，可采用请求级临时文件。请求缩略图按照片逻辑 ID、JPG 源版本和转换规格隔离；复用前执行零 Token 输入预检，校验可读性、格式/尺寸、来源与内容指纹，并将 JPG 原图规范化预览和待发送缩略图做本地视觉一致性比对。不匹配、不可读或无关联材料时在本地重建并记录异常，不调用 VLM；NEF 保持不参与 VLM/Embedding。
- **验收**：`DSC_1813.jpg` 的 VLM 请求缩略图可追溯到正确 JPG 原图；同名 JPG/NEF、跨目录同名、源图更新、材料损坏、视觉错配和正常复用均有测试。NEF 不得进入 VLM/Embedding，任一预检失败不得产生 VLM API 请求。

### AQL1-2 状态、任务与处理履历底座

- **目标**：持久化当前 AI 健康状态和每次处理结果，刷新或重启后仍可查询。
- **涉及模块**：SQLite 迁移与生成模型、Go DAO/服务、VLM 队列、Python EmbedQueue、状态查询。
- **方案**：每张照片维护预览图、VLM 请求缩略图、VLM、Embedding、总体健康、排除标记和版本关联；另记录批量/单张任务与阶段履历。统一待处理、处理中、健康、失败、待复核、过期、已排除的转移规则，运行时计数从任务结果派生。旧照片迁移后统一进入待审计，不误标健康。
- **验收**：单张 VLM 失败、批量 Embedding 失败和质量拒绝在照片详情、问题查询、任务摘要中结论一致，服务重启后仍可读取；无数据库外键。

### AQL1-3 VLM 质量闸门与失效传播

- **目标**：区分“调用返回文本”与“得到可信描述”，并立即使不可信上游的向量失效。
- **涉及模块**：Go VLM 服务、描述解析、状态服务、照片详情数据组装、VLM 测试。
- **方案**：仅接收已通过零 Token 输入预检的请求缩略图，再校验 VLM 输出非空和结构可解析；将故障彩条、纯色/空白、截图式描述等设为可解释的首批待复核规则，覆盖预检无法判断但模型输出明显异常的情况；描述重生成、质量拒绝或请求缩略图失效时统一使旧向量过期。支持确认误报、排除和从描述开始完整修复。
- **验收**：命中故障彩条规则的调用计为待复核而非成功，可见原因且不可检索；重新生成有效描述后才可进入向量阶段。

### AQL1-4 Embedding 一致性与检索准入

- **目标**：只有健康且描述版本一致的照片与组图封面进入三个向量集合和对话上下文。
- **涉及模块**：Python EmbedQueue、Chroma、RAG、组图集合同步、黄金用例评估、Python 测试。
- **方案**：Embedding 只领取健康描述并记录来源版本；待复核、失败、过期、已排除或版本不一致时清理全量和组图旧向量。查询、集合维护、黄金用例评估与对话 Trace 共用准入语义，评估先报告期望照片健康摘要。
- **验收**：已嵌入照片变为待复核/过期后，photo/fine/coarse 与对话都不再命中；恢复健康并重嵌入后才重新出现。

### AQL1-5 问题清单、队列结果与统一详情修复

- **目标**：用户不依赖日志或 SQL 即可发现、理解和修复问题照片。
- **涉及模块**：Go 查询接口/SDK、Python Agent 管理接口、Web 照片管理、PhotoDetail、类型与组件测试。
- **方案**：提供问题资产、单张健康详情、任务详情和受控修复能力；问题工作区支持状态/阶段/问题类型筛选、计数、跳转和确认后的批量操作。所有详情入口统一展示预览图与请求缩略图一致性、描述、向量来源、履历与下一步操作；队列区分成功、失败、待复核、跳过、取消并链接结果清单。
- **验收**：用户可定位 `DSC_1813.jpg` 并看见请求缩略图错配/待复核证据，修复后在同页得到健康结论；所有详情入口具备同等 AI 修复能力。

### AQL1-6 历史审计与受控修复

- **目标**：可重复、可预览、可中断地治理污染历史数据，原始照片不被改写。
- **涉及模块**：Go 审计服务/CLI、VLM 与 Embed 队列、Chroma 清理、问题清单、运行报告。
- **方案**：先只读核对 JPG 原图、预览图、请求缩略图、描述、向量和健康状态，按确定性错配与语义待复核分类；审计预览明确重建描述、清理向量、仅复核和无法自动修复的数量。用户确认范围后才启动修复，逐张写履历，停止后仅续跑未完成/失败项，最后产出治理报告。
- **验收**：审计报告覆盖已知异常集，修复前后差异可核对，停止/恢复不丢失结论，原始照片未被写入或删除。

### AQL1-7 黄金用例和对话质量回归

- **目标**：证明数据修复恢复用户场景，并建立后续检索优化可信基线。
- **涉及模块**：黄金用例管理与评估、对话 Trace、评估脚本、`docs/eval/baseline.md`。
- **方案**：为“佛像和人的合照1”保存资产健康前置检查及修复前后快照；以相同问题运行黄金用例和对话回归，记录命中、排名、回答与资产版本；将数据健康指标同 P@10/R@10/MRR 分开记录，并补齐 Go、Python、前端异常路径测试和端到端手工验收。
- **验收**：`DSC_1813.jpg` 健康后重新参与该黄金用例，评估/对话可追溯呈现修复前后差异，剩余低分可归因到数据、检索或回答生成。

## 产品定位决策

**从**：“个人摄影资产 AI 助手”（泛化，容易堆砌技术）
**到**：「AI 选题助手」，AI 像员工提案，用户像主编审阅。

核心 workflow：拍摄→入库→AI 定期推送选题建议（推荐照片组合 + 发角度）→用户判断选哪个、如何微调→用户自己发布。

**主动不做的事**：

- 不自动发布到社交平台（发送由用户操作）
- 不替代审美判断（AI 推荐，用户决策）
- 不做多模态检索/以图搜图（选题场景不需要）

## 拒绝清单
