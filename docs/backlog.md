## 产品定位决策

**从**："个人摄影资产 AI 助手"（泛化，容易堆砌技术）
**到**：「AI 选题助手」，AI 像员工提案，用户像主编审阅。

核心 workflow：拍摄→入库→AI 定期推送选题建议（推荐照片组合 + 发角度）→用户判断选哪个、如何微调→用户自己发布。

**主动不做的事**：

- 不自动发布到社交平台（发送由用户操作）
- 不替代审美判断（AI 推荐，用户决策）
- 不做多模态检索/以图搜图（选题场景不需要）

---

## 拒绝清单（明确砍掉的技术点及其理由）

以下方向已判定为"展示驱动"而非"需求驱动"，明确不做：

- **混合检索**：个人照片库检索准确率够用，混合检索的额外复杂度对选题场景无收益
- **RAG 重排序**：Top-K 精度不足前不做优化。先建评估基线再看是否必要
- **异步后台同步**：300 张照片，启动同步耗时可接受
- **Prometheus 监控**：单机个人工具，出问题看日志足够
- **本地 Embedding 模型**：300 张 Embedding 费用极低，无降本需求
- **proto-first 迁移**：API 数量少，手写维护成本低
- **语音输入**：选题场景无移动端需求
- **多语言支持**：中文用户不需要
- **负样本学习优化 Embedding**：数据量不足以支撑

### W1 Wails 工程搭建 + 嵌入现有前端

- **状态**：Done
- **背景**：需要一个 Windows 桌面客户端作为 Photo Agent 入口，最终内嵌 Web 视图展示 Photo Agent 界面。
- **方案**：在 `client/` 初始化 Wails 项目，Go 模块配置，将现有 Vue 3 前端集成到 WebView 中。前端适配 Vite 配置，API 代理指向本地运行的服务端。前端检测 `window.go.main.App` 区分 Wails/浏览器环境。
- **分析**：Wails v2.9.1 的 `wails build` 与 Go 1.24 不兼容（内部 `golang.org/x/tools` 版本过旧）。改用 `CGO_ENABLED=1 go build` 直接构建，前端资源 `//go:embed` 嵌入二进制。JS bindings 生成（W3 需要）留待后续处理。
- **验收**：
  - [x] Wails 项目结构就绪（`client/`：`main.go` / `app.go` / `go.mod` / `wails.json`）
  - [x] 前端构建流程：`build-frontend.sh` → `web/` 构建 → 复制到 `client/frontend/dist/`
  - [x] Go 编译通过，`CGO_ENABLED=1 go build` 成功生成二进制
  - [x] 前端资源嵌入验证通过（`strings` 确认 dist 文件在二进制中）
  - [x] 环境检测工具就绪（`web/src/utils/env.ts`）
  - [ ] 桌面窗口实际展示验证（需有图形环境的机器）

### W2 服务端 NEF 存储 + storage/info API

- **状态**：已规划
- **背景**：服务端需支持 NEF 文件存储（仅存储路径+文件名，不处理）和存储目录状态查询，为客户端上传同步提供支撑。
- **方案**：现有 `POST /api/v1/photos/upload` 识别 `.NEF` 后缀，跳过压缩/VLM/Embedding，直接存到对应目录并写入 DB（标记文件类型）。新增 `GET /api/v1/storage/info` 返回存储根路径的总文件数（JPG/NEF）、已有月份/活动文件夹、上次同步时间。支持文件夹命名 `YYYYMM/`（随手拍）和 `YYYYMM_活动名/`（有活动）。
- **分析**：-
- **验收**：
  - [ ] 可上传 NEF 文件并存到正确目录
  - [ ] storage/info 返回完整存储状态信息

### W3 客户端文件操作能力

- **状态**：已规划
- **背景**：客户端需要本地文件扫描、比对（full vs like vs nef）、EXIF 读取、拷贝/删除能力，通过 Wails 绑定暴露给前端。
- **方案**：Go 侧实现扫描 `full/`、`like/`、`nef/` 三目录，返回文件列表；比对逻辑：like 中有同名 JPG 的 NEF 保留，仅 full 有但 like 无的 NEF 标记删除；EXIF 读取拍摄时间并检测跨度异常；按确认结果执行文件拷贝/删除。全部通过 Wails 绑定暴露为 JS 函数。
- **分析**：-
- **验收**：
  - [ ] 扫描正确返回三目录文件数和文件列表
  - [ ] 比对逻辑正确——保留/删除分类准确

### W4 前端导入三步流程页面

- **状态**：已规划
- **背景**：在现有 Vue 3 前端新增 `#/import` 路由，实现导入工作流的完整 UI。
- **方案**：新增 ImportWorkflow 页面，分三步：
  1. 新建活动：日期选择+活动名称+中转路径 → 调用客户端 Go 创建目录 → 展示引导文字
  2. 分析报告：调用客户端 Go 扫描比对 → 展示统计/时间分布/操作明细 → 用户确认后执行
  3. 上传同步：输入服务器地址 → 调用 storage/info 验证 → 并行 upload（客户端控并发）→ 展示结果
     仅在 Wails 环境中显示导航入口。
