# 当前阶段合理性专项评估

> 评估对象：AR 系列完成后的当前工作区，重点覆盖 Agent 日志、Runtime 多步执行、RAG 黄金用例边界、对话页面交互，以及相关静态代码和自动验证。
>
> Agent Runtime 专题关联：[Agent Runtime 专题中枢](../../design/2026-08-31-2-agent-runtime-hub.md)。本报告不是常规功能评分，而是判断实现是否适合当前“单用户、本地摄影库、继续迭代”的阶段。

## 结论

- **当前阶段合理性：7.4/10，基本合理，但不宜直接归档。** AR 的核心闭环、预算和失败终态已经具备，现有自动测试全部通过；不过可观测性、运行等待体验和“检索评估样本”的语义边界有三处明确缺口。
- **优先问题**：OBS1（日志不可统一定位）、GQ1（非 RAG 回答可保存为黄金用例）、AR8（多步执行时用户只看到无状态等待）。三项都不会否定 AR 成果，但会让后续调试、评估数据和真实使用逐渐失真。
- **不作为问题记录的观察**：本地单用户开发阶段，日志中包含路由问题、模型原始 SQL 和运行参数，便于诊断；在没有多人访问或日志外发场景前，不按生产隐私标准额外引入脱敏/平台化日志。

## 评估维度

### 1. 运行时正确性与边界：7.8/10

- 得分点：Runtime 的状态归约、确定性完成检查、预算和失败终态相互独立。AR7 后，无效决策、能力异常和旅行未匹配不会再伪装为可继续任务。
- 得分点：实际 `agent.log` 记录的山西用例完成了旅行解析、SQL 候选、选片和文案四步，最终返回 6 张照片和文案；总耗时约 98 秒，未触发预算停止。
- 失分点（GQ1）：聊天页仅以“回答带照片”为条件展示“保存为黄金用例”。Runtime 的结果是选片与文案产物，不是“同一查询在固定 RAG 检索策略下的相关照片标注”；保存它会把创作选择混入 P@10/R@10/MRR 的检索基准。

### 2. 可观测性与故障定位：5.8/10

- 得分点：Runtime 已生成 `runtime.decide / execute / observe / check / trace_summary` JSONL 事件；单测能还原一条完整轨迹。
- 得分点：应用层日志带模块名和等级，SQL、Tool、Runtime 的关键路径已有针对性诊断。
- 失分点（OBS1）：`logs/agent.log` 是 `make` 输出重定向后的混合流，包含 Make、普通打印、应用日志和 Uvicorn access/startup 日志。应用日志格式为时间、模块和等级，不带文件与行号；Uvicorn 又使用另一种格式。因此同一请求的日志不能稳定按统一字段检索、跳转或关联。
- 失分点（OBS1）：同一请求的 `trace_id` 虽由消息接口返回，但前端响应类型和会话消息均未保存/呈现它；用户看到的对话结果与可重放的 Runtime JSONL 轨迹没有可见关联。

### 3. 页面交互与输出可理解性：6.8/10

- 得分点：对话结果明确标记 SQL、RAG、Tool、Combined、Runtime，照片附件可预览和查看连拍组；短请求的等待状态足够简洁。
- 失分点（AR8）：实际 Runtime 请求约 98 秒，页面从发送到完成只显示“思考中...”和旋转图标，同时禁用输入。用户不能区分正在检索、选片、生成文案还是已无进展，也没有对本次耗时任务的可见进度或停止入口。
- 失分点：页面把检索粒度标签展示在全部回答上。对 Runtime 创作任务而言，粒度不是用户可据此判断结果质量的主要语义，和“Runtime 多步”并列呈现容易暗示它仍是一条单次检索回答。

### 4. 静态代码与验证闭环：8.3/10

- 得分点：Runtime 的核心语义被拆为独立模块，入口图只承担分流和编排；177 个 Agent 单测覆盖 Runtime 成功、预算、异常、轨迹和入口注入。
- 得分点：后端 `GOTOOLCHAIN=local go test -count=1 ./...` 与 `go vet ./...` 通过；Web 的 Vitest 2/2 和 `pnpm build` 通过。
- 得分点：当前阶段不必为了“短文件”重拆大视图，`ChatView.vue` 的 755 行和 `GoldenQueryManagement.vue` 的 916 行尚未造成明确行为错误。
- 失分点：前端自动测试只覆盖两条基础工具用例，没有覆盖聊天消息的路由语义、黄金用例入口条件或 Runtime 等待态；上述 GQ1 和 AR8 因而能通过全部现有构建与测试。

## 证据与范围

- `logs/agent.log`：同一文件同时出现 Make 命令、`%(asctime)s [%(name)s] %(levelname)s` 应用日志、Uvicorn 默认日志和普通 `print`；应用日志没有源文件/行号。
- `web/src/views/ChatView.vue`：第 415–426 行仅凭 `msg.photos.length` 显示保存入口；第 347–349、446–451 行只显示通用“思考中”和 spinner。
- `agent/cli/server.py`：第 745–788 行创建并返回 `trace_id`，但会话写入未包含该字段；前端 `SendMessageResponse` 也没有它。
- `agent/cli/server.py`：第 2445–2465 行仅为应用包挂 StreamHandler，随后由 Uvicorn 另行配置运行日志。
- 自动验证：Agent `177` 项单测通过；后端全量测试与 vet 通过；Web `2` 项测试与生产构建通过。

## 待规划问题

- OBS1：Agent 服务日志混合多种来源和格式，应用记录缺少源文件/行号，且聊天结果无法关联其 Runtime trace。
- GQ1：非单纯 RAG 路由的回答仍显示并允许保存为黄金用例，可能污染检索评估数据。
- AR8：Runtime 多步任务的实际等待可达约 98 秒，页面仅显示无上下文 spinner，未呈现任务阶段或用户可理解的运行状态。
