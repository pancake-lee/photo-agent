# AR4 系列复评与执行合理性评估

> 评估对象：AR4-1 至 AR4-8 的当前工作区实现、离线回归与已记录的授权真实四轮回归。
> 评估范围：会话上下文、followup 路由与消解、Runtime 快照/局部续跑、补选确定性保障；不重新调用真实 LLM。

## 摘要

**总分 8.0/10，通过（阈值 6.0）**。AR4 已用一轮真实四轮会话验证关键主线，且 AR4-8 针对真实回归首次暴露的“补选不新增”问题，把保障下沉到完成要件，修复后真实复验通过。执行路径符合 V4 的范围决策：先以离线金用例建立边界，再以授权 live 回归购买模型行为证据，发现模型行为依赖后增加最小确定性约束。

长会话截断仍有一个 P2 正确性缺口：上下文丢弃最早轮次后，对剩余轮次重新从 1 编号，序数指代可能错绑。登记 AR4-9。本轮还发现一项不影响功能的 F541 lint 违规，登记 AR4-10。

## 分维度评分

### 代码质量（8.2）

- **正确性 7.8**
  - 得分点：`selection_add` 同时重开 select/copy，保留集由归约层去重合并；完成检查在 select 仍待办时拒绝把保留集当作新增完成。图级回归覆盖“模型先写文案、后被强制选片”的真实缺陷形态。
  - 失分点：构造 10 轮会话后，实际第 3–10 轮被展示为第 1–8 轮。对“第二组”“第六轮”的序数指代，消解器会接收错误的轮次标签，长程指代正确性不再成立（AR4-9）。
- **健壮性 8.2**
  - 得分点：快照损坏可退回新任务；补选状态在范围失效、重选与仅改文案时均清理，避免跨轮泄漏；live 脚本先探测后端并关闭重试，避免不可用环境的无谓消耗。
  - 失分点：轮次截断只暴露 `truncated` 布尔值，历史块没有说明被省略的轮次范围，放大了 AR4-9 的歧义。
- **可维护性 8.3**
  - 得分点：上下文构建、状态归约、完成判定与 live 断言职责分离，关键补选语义有图级和纯函数两层测试。
  - 失分点：`runtime_task_dump` 仍以 JSON 字符串穿透路由状态；此外 `state.py` 有一处 F541 无插值 f-string，所选 AR4 文件不能完整通过 Ruff（AR4-10）。
- **简洁性 8.4**
  - 得分点：补选保障只增加一个 affect 值、一个保留字段与完成要件条件，未引入 Planner 或跨任务 Memory 等未被证据支持的复杂度。

### 功能效果（8.3）

- **准确性 8.3**
  - 得分点：授权真实回归四轮 PASS：首轮 Runtime 交付；第二轮识别为 followup 且只重开 copy；第三轮正确声明 `selection_add`、先重跑选片并从 1 张扩至 2 张；第四轮新问题未误判 followup，路由 SQL 并返回 136。
  - 失分点：真实证据覆盖的是四轮会话，尚不能证明 AR4-9 所在的超过 8 轮序数指代路径。
- **完整性 8.0**
  - 得分点：AR4-1 至 AR4-8 的既定验收均已有代码、离线测试或真实回归证据，AR4-5/8 不再停留在“待授权”状态。
  - 失分点：AR4-6 的“长程指代可展开”验收只验证 ID 可见，未验证截断后的原始轮次身份，形成 AR4-9。
- **一致性 8.5**
  - 得分点：407 项全量离线回归通过；首条消息与非 followup 路径保持原有行为；脚本与既有 live 回归一致地隔离在独立目录。

### V4 专项与执行合理性

- **Context Sufficiency 7.5**：照片 ID 及用户约束被有界保留，但历史的相对轮次身份在截断后失真；对序数指代而言，信息并非充分。
- **Context Utilization 8.5**：历史只注入分类/消解，执行节点消费独立的 `effective_question`，局部续跑不会重复执行未失效步骤。
- **Constraint Retention 9.0**：当前约束优先、范围失效清理事实、补选保留集程序性合并均有确定性断言。
- **Multi-turn Task Success 8.3**：一条真实四轮主线和图级回归都通过；评分受长会话序数指代未覆盖影响。
- **执行合理性 8.2**：V4 没有提前实现全量 Planner/Replan 或跨任务 Memory，符合“复杂度由证据购买”；AR4-8 由真实失败触发且只约束补选续跑，责任层与影响面合理。失分在于 AR4-6 的验证指标把“ID 可见”当作长程指代充分性的替代，没有核验轮次身份保持。

## 任务简评

- **AR4-1：7.8**。选择、压缩和引用的主体成立；截断后的轮次重编号使其长会话语义不完整。
- **AR4-2：8.2**。真实 followup 分类与消解已通过一条主线；长程序数指代仍受 AR4-9 限制。
- **AR4-3：8.4**。快照往返、目标匹配与局部失效边界清楚。
- **AR4-4：8.3**。金用例和基线可重复；缺少超过截断阈值的序数指代断言。
- **AR4-5：8.6**。脚本工程质量与授权真实四轮 PASS 共同闭环。
- **AR4-6：7.5**。ID 引用补齐了此前缺口，但没有保持原始轮次身份。
- **AR4-7：8.5**。旧入选保留落在归约层，幂等和兼容性均有测试。
- **AR4-8：8.7**。针对真实故障作了最小、确定性的完成要件修复，并经真实补选成功复验。

## 评估结论

AR4 主线可继续作为 V4 的已交付能力使用，且不需要因本轮发现而引入更大架构。AR4-9 影响很长会话中的序数指代，应在下一次规划时处理；AR4-10 为低风险代码卫生问题。
