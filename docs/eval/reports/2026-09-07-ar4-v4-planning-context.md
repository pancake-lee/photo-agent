## 摘要

**总分 8.3/10，通过（阈值 6.0，本轮循环目标 8.0）**。会话多轮连续性与历史上下文两条 V0-V3 遗留缺口（AR16/AR17）在本轮闭环：历史经 Context Builder 选择压缩后进入推理链路，跟进消息不再被当全新请求，Runtime 任务快照支持局部失效续跑。离线全量 369/369 通过，未调用真实 LLM；真实会话质量验证登记为 AR4-5 待授权执行。

## 分维度评分

### 代码质量（8.4）

- **正确性 8.5**
  - 得分点：局部失效语义（`resume_task` 词汇表驱动）、序列化往返一致性、约束合并且当前优先均有直接断言（`tests/test_runtime_resume.py` 14 项）；开发中走查发现并修复了两个真 bug，AFFECT_COPY 只重开里程碑未清旧文案会让完成要件瞬间满足跳过重写、消解声明的目标类型与快照目标不一致时在旧目标上错误续跑，两者均有回归测试锚定。
  - 失分点：分类与消解提示词的效果依赖真实 LLM，离线替身只能断言注入与解析契约，不能证明识别质量。
- **健壮性 8.0**
  - 得分点：快照损坏降级全新任务并告警；消解输出经目标词表与受影响部分词表双重校验，非法值兜底 rag 与既有分类兜底同一惯例；澄清续跑路径（AR11 遗产）与快照/历史完全隔离，行为与 V3 逐字一致。
  - 失分点：历史块超长轮次丢弃只体现在返回值 `truncated` 标记，未进入提示词或日志提示，长会话用户无感知。
- **可维护性 8.5**
  - 得分点：Context Builder 为框架无关纯模块（输入纯消息字典，不 import 其他功能包），符合 cli → internal → infra 分层与 internal 包间禁 import 规则；resume 语义集中在 state.py，路由侧只做接线；限定导入、同级同构注释对齐等编码规范一致。
- **简洁性 8.5**
  - 得分点：逐项截断（轮数 + 单条 + 引用上限）自然有界，评估过程中发现并删除了永不可达的总长截断死分支；受影响部分用常量词表驱动，未引入抽象层。
  - 失分点：`runtime_task_dump` 以 JSON 字符串穿透 RouterState（节点内 dumps、服务层直接存储），序列化责任分散在两处。

### 功能效果（8.2）

- **准确性 8.0（离线口径）**：替身下消解改写保留原约束并合并新要求、续跑第一轮决策可见已选照片与待办、copy 失效仅 1 次决策完成不重跑选片，均由断言锁定。
- **完整性 8.0**：AR16（连续性：识别、消解、五路径接入、快照续跑）与 AR17（选择、压缩、引用、优先级）全量闭环；Server 与 CLI sessions resume 双入口接线。失分点：跨任务 Memory 与完整 Planner 按决策不在本轮（不计缺失），但 06 文档「Memory 读取与冲突」一节没有任何对应机制边界落点，仅在 tech.md 以一句延后说明。
- **一致性 8.5**：无历史会话分类提示词与 V3 字节一致；澄清续跑回归不变；369 全量测试含全部存量用例通过；前端无新增交互契约（followup 是路由内部中间态，最终 query_type 仍为五类之一）。

### V4 专项（06 文档验收，适用四维，8.5）

- **Context Sufficiency 8.0**：当前决策所需信息（范围、候选、已选、待办、约束、历史块）在分类/消解/决策提示词中可见，金用例断言。失分点：更早轮次摘要只有问题原文与回答首行加照片计数，3 轮以前的交付物细节不可展开（登记 AR4-6）。
- **Context Utilization 8.5**：历史块有界（逐项截断）且只注入分类与消解两个调用点，五条执行路径不重复携带历史；续跑不重跑未失效里程碑，copy 失效场景全程仅 1 次 LLM 决策。
- **Constraint Retention 9.0**：三重保障均有断言，更早轮次用户约束原文进摘要、约束字典合并当前优先、范围失效重建时 resolved_facts 清空不泄漏旧事实。
- **Multi-turn Task Success 8.5**：四条金用例覆盖改文案、补选重写、换范围全链路、快照 JSON 往返。失分点：补选时旧照片保留依赖选片模型行为，无确定性规则（登记 AR4-7）。

- **AR4-1（8.4）**：构建器职责单一、边界清楚；truncated 未对外呈现是小缺口。
