# 图文工坊 PS1-PS6 系列 — 评估报告

> **总分**：8.1/10 ✅ 通过（阈值 6.0，复评）
> **评估对象**：PS1 草稿与核心页面、PS2 自选入口、PS3 选题采纳、PS4 导出、PS5 详情灯箱、PS6 文案提示词重构。

## 摘要

图文工坊已形成“自选/采纳 → 编辑生成 → 草稿 → 导出”的完整闭环。PS6 修复了照片描述未进入提示词的根因：真实照片生成结果能提到河岸、人物、竹筏、山峰，并在攻略模式使用了相机参数。详情读写边界、草稿清空和默认提示词策略均为低优先级未来优化，不影响当前评分。

## 验收与运行证据

- 三个服务健康：backend `GET /api/v1/health`、agent `GET /api/chat/health`、web 均为可用状态。
- `GOTOOLCHAIN=local go test ./...` 通过；`agent/chain/test_post_studio_smoke.py` 6/6 通过；`web` 的 `pnpm build` 通过。
- `POST /api/post-studio/generate` 空照片返回 400“需要至少一张照片”；`refine` 空正文返回 400“内容不能为空”。
- 真实一张有 VLM 描述的照片在 3.5 秒返回 200，文案与河岸、人物、竹筏和山峰相符。三张照片攻略风格返回 200，输出引用 35mm、f/1.7、ISO 6400 等对应 EXIF。
- PS2、PS3、PS4、PS5 的入口、路由、组内选择、灯箱导航及 ZIP 实现已逐项代码审查。主题发现采纳的设计文档验收项已据实现回写。
- 未完成运行时核验：拖拽后叙事顺序变化、四种风格的实际差异、带照片润色不新增草稿外事实、浏览器中的完整导出交互。

## 代码质量

### 正确性 8.5

得分点：草稿 CRUD/迁移、两条入口和导出链路完整；PS6 通过 SDK 获取 `detail.photo`，并以 JSON 契约解析模型输出。空参数错误路径也有明确 API 反馈。

失分点：草稿、导出与入口流程缺少专门的端到端行为测试，当前验证主要由代码审查和核心运行路径组成。

### 健壮性 7.5

得分点：无照片、空草稿、全无描述和 AI 格式异常都有明确错误处理；部分无描述会返回 warning。

失分点：草稿、导出与入口流程没有专门的后端集成测试或前端行为测试；多个关键验收仍只有代码覆盖证据。

### 可维护性 7.5

得分点：PS6 将提示词主流程从 `server.py` 拆到 `post_studio.py`，SDK 与现有 suggest 模块复用合理；共享 `PhotoDetail` 避免了两套灯箱。

失分点：`PostStudio.vue` 同时承担路由加载、照片/连拍组管理、生成、草稿和导出，职责密集；共享组件的只读能力未覆盖元数据编辑。

### 简洁性 8.0

得分点：四层提示词、单一 `STYLE_MAP`、前端文本导出和后端 ZIP 导出边界清楚，无明显重复链路。

失分点：`DEFAULT_PROMPT` 在 PS6 后仍保留旧通用话术，和系统提示词职责重复。

## 功能效果

### 准确性 8.0

得分点：真实生成输出已具备画面关联，攻略输出使用了真实 EXIF；采纳入口按选题详情预填照片、标题和理由。

失分点：未取得拖拽重排与润色事实边界的实际输出证据。

### 完整性 8.0

得分点：PS1-PS6 的核心设计范围均已落到代码，两个创作入口最终汇聚到同一编辑页。

失分点：PS6 有四项体验验收尚未完整实测，包含拖拽重排后的叙事顺序、四种风格的实际差异和润色事实边界。

### 一致性 8.5

得分点：Vue 路由、NaiveUI 组件和 Go API 命名保持项目既有模式；图文工坊/图片管理使用相同灯箱交互。

失分点：默认提示词与系统提示词的职责划分和 PS6 设计不一致。

## 用户价值

- **惊喜度 7.5**：AI 已能将实际照片素材转为成稿，攻略模式尤其具有照片库之外的参数整合价值。
- **可用性 8.5**：从选片、采纳到保存和导出能完成发布前工作，已填写内容可以修改后保存。
- **交互体验 8.0**：双入口、模式切换和灯箱导航顺畅；详情编辑与默认提示词策略作为后续可选优化处理。
- **AI 增量 8.5**：VLM 摘要、时间跨度、EXIF 与风格约束共同提供了非简单模板可得的画面化文案。
