# 重启状态检查与目录缺失修复

## 原因与处理

- 环境设置了 HTTP/HTTPS/ALL_PROXY，没有本机免代理名单。curl 健康检查和 Python requests 的后端访问被送到外部代理。
- make 合并已有 NO_PROXY/no_proxy，补充 localhost、127.0.0.1、::1，并向服务子进程导出。状态检查显式直连，连接超时 1 秒、总超时 3 秒。
- 用户手动删除 `未知年月-散片`，数据库保留 `DSC_0390.JPG`。原同步函数把单活动缺失作为全局错误，导致列表、统计、时间线等请求均为 500。
- 缺失活动改为告警并保留待确认数据，其他活动继续可用。不会根据一次文件系统缺失自动删除记录或恢复文件。
- 用户明确要求保留删除后，维护命令确认源目录不存在、预览身份匹配且没有未确认文件，再清理 1 条照片、收藏与预览残留。保留 purged 墓碑供原有向量清理机制使用。
